# Стратегия тестирования и План (Testing Strategy)

Этот документ определяет комплексную стратегию автоматизированного тестирования для проекта, основанную на классической модели **пирамиды тестирования**. План структурирован по уровням для обеспечения максимального покрытия и качества.

---

## Уровень 1: Модульные тесты (Unit Tests)

**Цель:** Проверить корректность работы отдельных классов и методов в полной изоляции от Android SDK, базы данных и сети. Это самые быстрые и стабильные тесты.

**Инструменты:** JUnit 5, MockK, Truth, `@Tag("unit")`.

### Чек-лист:

- **`ViewModels`**
    - [x] `ProductCatalogViewModel`: Проверить вызов нужных методов DAO при сортировке.
    - [x] `ProductCatalogViewModel`: Проверить логику визуальных изменений (`generateVisualChanges` и `findProductByName`).
    - [x] `ProductDetailViewModel`: Проверить вызов DAO для получения продукта по ID.
    - [x] `SplashViewModel`: Проверить вызов DAO для вставки и получения продуктов.
- **`Utils` и `Converters`**
    - [x] `Methods`: Проверить расчет общей стоимости (`getTotalPrice`).
    - [x] `Methods`: Проверить валидацию пароля (`isValidPassword`).
    - [x] `Methods`: Проверить сравнение строк (`isEqual`).
    - [x] `Methods`: Проверить подсчет общего количества товаров (`getTotalNum`).
    - [x] `ColorModelConverters`: Проверить корректность JSON-сериализации и десериализации.
- **Логика валидации `LoginFragment`**
    - [x] Проверить валидацию полей и логику проверки заблокированного пользователя.

---

## Уровень 2: Интеграционные тесты (Integration Tests)

**Цель:** Проверить корректность взаимодействия между несколькими компонентами системы.

**Инструменты:** JUnit 5, `AndroidJUnitRunner`, Room Testing, MockWebServer, `@Tag("database")`, `@Tag("api")`.

### Чек-лист:

- **Интеграция с базой данных (Room)**
    - [x] `AppDao`: Проверить, что после вставки (`insertProduct`) продукт корректно извлекается (`getAllProducts`, `getProduct`).
    - [x] `AppDao`: Проверить, что продукт корректно удаляется (`delete`).
    - [x] `AppDao`: Проверить, что методы сортировки (`getPersonsSortBy...`) возвращают список в правильном порядке.
- **Интеграция с сетью (API)**
    - [ ] **Рефакторинг `Network.java`:** Сделать класс тестируемым путем избавления от статических методов и жестко заданных URL. Внедрять зависимости (URL или HTTP-клиент) через конструктор.
    - [ ] **Тестирование с `MockWebServer` (после рефакторинга):**
        - [ ] Проверить корректность формирования GET-запроса: правильный путь, метод.
        - [ ] Проверить добавление обязательных заголовков (`User-Agent`, `X-Trace-ID`).
        - [ ] Проверить корректную обработку успешного ответа (200 OK) и возврат данных.
        - [ ] Проверить обработку ошибок клиента (например, 404 Not Found) и сервера (например, 500 Internal Server Error).
- _(Примечание: Рефакторинг сетевого слоя будет проведен до написания интеграционных тестов для него, под защитой существующих UI-тестов)._

## Уровень 3: UI-тестирование (Пирамида UI-тестов)

**Цель:** Проверить приложение с точки зрения конечного пользователя, применяя пирамидальный подход и к UI-тестам. Это позволяет эффективно распределить усилия: много быстрых тестов на отдельные экраны и мало медленных сквозных сценариев.

**Инструменты:** Espresso, Kakao, Kaspresso, JUnit 5, `@Tag("ui")`.

### 3.1. Espresso: Базовые компонентные тесты

**Цель:** Продемонстрировать использование "чистого" Espresso API (`onView`, `check`, `perform`) для самых простых проверок на изолированных экранах.
**Инструменты:** `FragmentScenario`, `Espresso`, `@Tag("espresso")`, `@Tag("component-ui")`.

- [ ] **Экран "О приложении" (`AboutFragment`)**
    - [ ] **Отображение:** Проверить видимость всех текстовых полей и их содержимое.
- [ ] **Экран завершения заказа (`CheckoutCompleteFragment`)**
    - [ ] **Отображение:** Проверить видимость заголовка "Thank you for your order!" и кнопки "CONTINUE SHOPPING".


### 3.2. Kakao: Читаемые компонентные и навигационные тесты

**Цель:** Покрыть базовую функциональность, изолированные экраны и простые пользовательские сценарии. Эти тесты станут фундаментом для рефакторинга UI-слоя.

#### 3.2.1. Модульные UI-тесты (Screen/Component Tests)

- [ ] **Экран логина (`LoginFragment`)**

    - [ ] **Валидация:** Проверить появление сообщений об ошибках при отправке пустых полей.
    - [ ] **Автозаполнение:** Проверить, что клик по стандартному пользователю заполняет поля логина и пароля.
    - [ ] **Неудачная авторизация:** Ввести неверные логин/пароль -> Проверить отображение сообщения об ошибке.
    - [ ] **Вход заблокированным пользователем:** Ввести данные заблокированного пользователя (`alice@example.com`) -> Проверить отображение сообщения о блокировке.
    - [ ] **Переходы:** Проверить, что при клике на ссылки создается корректный `Intent` для открытия браузера.
    - [ ] **Отсутствие браузера:** Проверить, что при отсутствии браузера отображается `Toast` сообщение.
- [ ] **Экран каталога (`ProductCatalogFragment`)**
    - [ ] **Отображение:** Проверить, что список товаров загружается и отображается корректно.
    - [ ] **Пустой каталог:** Проверить отображение заглушки или пустого состояния, если товаров нет.
    - [ ] **Сортировка:** Проверить, что диалог сортировки открывается и базовый функционал работает.
    - [ ] **Применение сортировки:** Проверить, что выбор опции сортировки (`NAME_ASC`, `PRICE_DESC` и т.д.) корректно обновляет список товаров.
    - [ ] **Визуальные изменения:** Проверить, что при логине пользователя `visual@example.com` применяются визуальные изменения к элементам каталога.
- [ ] **Экран корзины (`CartFragment`)**
    - [ ] **Пустое состояние:** Проверить отображение заглушки "No Items" при пустой корзине.
    - [ ] **Заполненное состояние:** Проверить отображение списка товаров, количества и итоговой суммы (с моковыми данными).
- [ ] **Экраны оформления заказа (компонентные тесты)**
    - [ ] **`CheckoutInfoFragment`:** Проверить валидацию полей (появление ошибок при пустых полях).
    - [ ] **`CheckoutFragment`:** Проверить валидацию полей и логику скрытия/отображения адреса.
    - [ ] **`PlaceOrderFragment`:** Проверить корректное отображение суммарной информации о заказе (с моковыми данными).
    - [ ] **`PlaceOrderFragment`:** Проверить, что при успешном заказе происходит переход на экран `CheckoutCompleteFragment`.
    - [ ] **`ProductDetailFragment`:** Проверить отображение деталей продукта, работу счетчика количества, выбор цвета.
    - [ ] **`ProductDetailFragment`:** Проверить добавление товара в корзину с разным количеством и цветом.
    - [ ] **`ProductDetailFragment`:** Проверить, что при количестве 0 кнопка "Add to cart" неактивна.
    - [ ] **`ProductDetailFragment`:** Проверить работу системы рейтинга (выбор звезд).
    - [ ] **`CheckoutCompleteFragment`:** Проверить отображение экрана благодарности.
    - [ ] **`CheckoutCompleteFragment`:** Проверить, что кнопка "Shop Now" очищает корзину и возвращает на главный экран.
- [ ] **Экран ввода URL (`WebAddressFragment`)**
    - [ ] **Валидация:** Проверить появление ошибки при вводе некорректного URL.
    - [ ] **Валидация:** Проверить появление ошибки при вводе пустого URL.
    - [ ] **Обработка некорректного URL:** Ввести URL, который не может быть открыт WebView -> Проверить отображение ошибки.
 - [ ] **`WebViewFragment`:**
    - [ ] **Отображение загрузки:** Проверить, что во время загрузки страницы отображается индикатор загрузки.

#### 3.2.2. Интеграционные UI-тесты (Navigation Tests)
**Инструменты:** `ActivityScenarioRule`, `Kakao`, `@Tag("kakao")`, `@Tag("navigation-ui")`.

- [ ] **Сценарий успешной авторизации:**
    - [ ] Ввести валидные данные на экране логина -> Нажать "Login" -> Проверить, что открылся экран каталога.
- [ ] **Сценарий просмотра товара:**
    - [ ] На экране каталога нажать на первый товар -> Проверить, что открылся экран деталей (`ProductDetailFragment`) с корректными данными.
- [ ] **Сценарий добавления товара в корзину:**
    - [ ] На экране деталей товара нажать "Add to cart" -> Перейти в корзину -> Проверить, что товар появился в списке.
- [ ] **Сценарий перехода к WebView:**
    - [ ] На экране `WebAddressFragment` ввести валидный URL -> Нажать "Go" -> Проверить, что открылся `WebViewFragment`.
- [ ] **Сценарий оформления заказа (частичный):**
    - [ ] Добавить товар в корзину -> Перейти в корзину -> Нажать "Proceed to Checkout" -> Проверить переход на `CheckoutInfoFragment`.
- [ ] **Сценарий оформления заказа без авторизации:**
    - [ ] Добавить товар в корзину -> Перейти в корзину -> Нажать "Proceed to Checkout" -> Проверить переход на `LoginFragment`.

### 3.3. Kaspresso: Системные E2E и сложные тесты

**Цель:** Проверить сложные пользовательские сценарии, взаимодействие с компонентами ОС и обеспечить максимальную стабильность для критически важных интеграционных проверок.

- [ ] **Работа с геолокацией и разрешениями (`LocationFragment`)**:

#### 3.3.2. Сквозные тесты (End-to-End Tests)
**Инструменты:** `Kaspresso`, `@Tag("kaspresso")`, `@Tag("e2e")`.

- [ ] **`[E2E-1]` Полный цикл покупки (Happy Path):** Авторизация -> Выбор товара -> Добавление в корзину -> Проверка корзины -> Оформление заказа (все шаги) -> Проверка экрана "Thank you for your order".
- [ ] **`[E2E-2]` Вход заблокированным пользователем:** Ввести данные заблокированного пользователя -> Проверить отображение корректной ошибки на экране логина.
- [ ] **`[E2E-3]` Сброс состояния приложения:** Добавить товары в корзину -> Через боковое меню выполнить "Reset App State" -> Проверить, что корзина пуста.

- _(Примечание: После написания этих тестов будет проведен этап рефакторинга для улучшения кода UI-компонентов)._
