[[section-what-is-mockk]]
== Что такое MockK?

**MockK** — это современный фреймворк для мокирования, написанный специально для Kotlin. Он позволяет создавать "заглушки" (моки) для классов и объектов, чтобы изолировать тестируемый компонент от его зависимостей.

В модульном тестировании мы хотим проверить только один класс (например, `ViewModel`), а не всю цепочку вызовов до базы данных или сети. MockK позволяет нам подменить репозиторий или сервис фейковым объектом, поведение которого мы полностью контролируем.

[[section-why-mockk]]
== Почему MockK, а не Mockito?

Хотя Mockito — отличный фреймворк для Java, MockK предлагает ряд ключевых преимуществ именно для Kotlin-разработчиков:

1.  **Идиоматичный DSL:** MockK использует функции высшего порядка и лямбда-выражения, что делает код тестов более чистым и похожим на обычный Kotlin-код.
    *   Mockito: `when(repository.getData()).thenReturn(result)`
    *   MockK: `every { repository.getData() } returns result`

2.  **Поддержка Kotlin-специфичных фич:** MockK "из коробки" поддерживает мокирование:
    *   **Корутин** (`suspend` функций).
    *   **Объектов** (`object`) и `companion object`.
    *   **Функций-расширений** (extension functions).
    *   **Функций верхнего уровня.**

3.  **Нет проблем с `final` классами:** В Kotlin классы по умолчанию `final`. Mockito требует специальной настройки для их мокирования, в то время как MockK справляется с этим без дополнительных усилий.
