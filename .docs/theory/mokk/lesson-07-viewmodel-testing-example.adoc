[[section-viewmodel-test]]
== Тест для `ProductCatalogViewModel`

```kotlin
import com.example.app.data.DatabaseRepository
import com.example.app.data.Product
import com.example.app.ui.product_catalog.ProductCatalogViewModel
import com.example.app.utils.InstantExecutorExtension
import com.example.app.utils.getOrAwaitValue
import io.kotest.matchers.shouldBe
import io.mockk.every
import io.mockk.impl.annotations.MockK
import io.mockk.junit5.MockKExtension
import io.mockk.verify
import org.junit.jupiter.api.BeforeEach
import org.junit.jupiter.api.Test
import org.junit.jupiter.api.extension.ExtendWith

@ExtendWith(MockKExtension::class, InstantExecutorExtension::class)
class ProductCatalogViewModelTest {

    @MockK
    private lateinit var repository: DatabaseRepository

    private lateinit var viewModel: ProductCatalogViewModel

    @BeforeEach
    fun setUp() {
        // MockKExtension автоматически инициализирует поля с @MockK
        viewModel = ProductCatalogViewModel(repository)
    }

    @Test
    fun `loadProducts should call repository and update LiveData`() {
        // 1. Arrange (Подготовка)
        val mockProducts = listOf(Product(1, "Mock Product", 99.9, 1))
        val liveData = MutableLiveData(mockProducts)

        // "Обучаем" мок-репозиторий
        every { repository.getProducts() } returns liveData

        // 2. Act (Действие)
        viewModel.loadProducts()

        // 3. Assert (Проверка)
        // Проверяем, что LiveData во ViewModel обновилась
        val products = viewModel.products.getOrAwaitValue()
        products shouldBe mockProducts

        // Проверяем, что метод репозитория был вызван
        verify(exactly = 1) { repository.getProducts() }
    }
}
```

=== Что здесь происходит?

1.  **`@ExtendWith(MockKExtension::class, ...)`**: `MockKExtension` — это расширение JUnit 5 от MockK, которое автоматически создает моки для полей, аннотированных `@MockK`.
2.  **`@MockK`**: Аннотация, которая помечает поле как мок, который нужно создать.
3.  **`every { repository.getProducts() } returns liveData`**: Мы настраиваем наш мок. Говорим ему, что при вызове `getProducts()` он должен вернуть заранее подготовленный `LiveData` с нашими тестовыми продуктами.
4.  **`viewModel.loadProducts()`**: Вызываем тестируемый метод. Внутри он вызовет `repository.getProducts()`.
5.  **`products shouldBe mockProducts`**: Проверяем, что `ViewModel` корректно выставила данные, полученные от репозитория, в свою `LiveData`.
6.  **`verify(exactly = 1) { repository.getProducts() }`**: Убеждаемся, что `ViewModel` действительно вызвала нужный метод у репозитория ровно один раз.

Этот тест полностью изолирован. Он не зависит ни от реальной базы данных, ни от UI, проверяя только логику `ProductCatalogViewModel`.
