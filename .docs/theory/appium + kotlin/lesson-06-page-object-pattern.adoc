Как и в UI-тестах на Espresso/Kaspresso, в Appium-тестах критически важно использовать паттерн **Page Object** для создания чистых, читаемых и поддерживаемых тестов.

[[section-page-object-recap]]
== Принцип Page Object

*   **Класс Page Object:** Представляет один экран приложения. Он содержит локаторы всех элементов на этом экране и методы для взаимодействия с ними.
*   **Тестовый класс:** Использует объекты страниц для выполнения высокоуровневых действий, не заботясь о деталях реализации (локаторах и кликах).

[[section-example]]
== Пример: Рефакторинг теста на вход в систему

=== Шаг 1: Создаем Page Object для экрана логина

```kotlin
import io.appium.java_client.AppiumBy
import io.appium.java_client.android.AndroidDriver

class LoginScreen(private val driver: AndroidDriver) {

    // Описываем локаторы
    private val usernameField by lazy { driver.findElement(AppiumBy.id("com.example.app:id/username_input")) }
    private val passwordField by lazy { driver.findElement(AppiumBy.id("com.example.app:id/password_input")) }
    private val loginButton by lazy { driver.findElement(AppiumBy.id("com.example.app:id/login_button")) }

    // Описываем высокоуровневые действия
    fun typeUsername(username: String) {
        usernameField.sendKeys(username)
    }

    fun typePassword(password: String) {
        passwordField.sendKeys(password)
    }

    fun clickLoginButton() {
        loginButton.click()
    }

    fun login(username: String, password: String) {
        typeUsername(username)
        typePassword(password)
        clickLoginButton()
    }
}
```

=== Шаг 2: Используем Page Object в тесте

```kotlin
class LoginAppiumTest : BaseAppiumTest() {

    @Test
    fun successfulLogin_opensProductCatalog() {
        val loginScreen = LoginScreen(driver)
        loginScreen.login("standard_user", "secret_sauce")

        val productCatalogScreen = ProductCatalogScreen(driver)
        assertThat(productCatalogScreen.isTitleDisplayed()).isTrue()
    }
}
```

**Преимущества:**
*   **Читаемость:** Тест читается как пользовательский сценарий.
*   **Поддерживаемость:** Если ID кнопки изменится, вам нужно будет исправить его только в одном месте — в `LoginScreen`.
*   **Переиспользуемость:** Метод `login()` можно использовать в десятках других тестов.
