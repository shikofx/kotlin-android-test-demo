После того как элемент найден, с ним можно взаимодействовать. API для этого очень похоже на Selenium WebDriver.

[[section-actions]]
== Основные действия

*   `click()`: Нажатие на элемент.
*   `sendKeys("text")`: Ввод текста.
*   `clear()`: Очистка текстового поля.
*   `getText()`: Получение текста элемента.
*   `isDisplayed()`: Проверка, видим ли элемент.
*   `isEnabled()`: Проверка, активен ли элемент.
*   `getAttribute("attribute-name")`: Получение значения атрибута (например, `getAttribute("text")` или `getAttribute("content-desc")`).

[[section-example]]
== Пример теста на вход в систему

```kotlin
import io.appium.java_client.AppiumBy
import org.junit.jupiter.api.Test
import com.google.common.truth.Truth.assertThat

class LoginAppiumTest : BaseAppiumTest() {

    @Test
    fun successfulLogin_opensProductCatalog() {
        val usernameField = driver.findElement(AppiumBy.id("com.example.app:id/username_input"))
        val passwordField = driver.findElement(AppiumBy.id("com.example.app:id/password_input"))
        val loginButton = driver.findElement(AppiumBy.id("com.example.app:id/login_button"))

        usernameField.sendKeys("standard_user")
        passwordField.sendKeys("secret_sauce")
        loginButton.click()

        // Проверяем, что открылся следующий экран, найдя его заголовок
        val title = driver.findElement(AppiumBy.xpath("//*[@text='Products']"))
        assertThat(title.isDisplayed).isTrue()
    }
}
```

**Важный момент:** Appium не имеет такой же автоматической синхронизации, как Espresso. Если элемент появляется не сразу, тест может упасть. Для решения этой проблемы используются **явные ожидания (Explicit Waits)**, которые мы рассмотрим в более продвинутых уроках.
