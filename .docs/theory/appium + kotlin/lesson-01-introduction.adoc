[[section-what-is-selenide]]
== Что такое Selenide?

**Selenide** — это фреймворк-обертка над Selenium WebDriver, который ставит своей целью сделать тесты более короткими, читаемыми и стабильными. Поскольку Appium построен на тех же принципах, что и Selenium, мы можем использовать Selenide для автоматизации мобильных приложений.

Если Appium — это набор низкоуровневых инструментов, то Selenide — это высокоуровневый DSL, который берет на себя всю "грязную" работу.

[[section-problems-selenide-solves]]
== Какие проблемы Appium решает Selenide?

1.  **Явные ожидания (Explicit Waits):** В чистом Appium вам постоянно нужно писать код для ожидания появления элементов (`WebDriverWait`). Selenide делает это **автоматически**. Когда вы обращаетесь к элементу, Selenide сам ждет его появления в течение заданного таймаута.

2.  **Громоздкий поиск элементов:** Вместо `driver.findElement(By.id(...))` вы пишете лаконичное `$(By.id(...))`.

3.  **Нечитаемые проверки:** Вместо `assertThat(element.isDisplayed()).isTrue()` вы пишете `element.shouldBe(visible)`.

4.  **Управление драйвером:** Selenide может упростить управление жизненным циклом драйвера.

=== Сравнение "До" и "После"

*Чистый Appium:*
```kotlin
val wait = WebDriverWait(driver, Duration.ofSeconds(10))
val element = wait.until(ExpectedConditions.visibilityOfElementLocated(AppiumBy.id("...")))
element.click()
assertThat(element.text).isEqualTo("Hello")
```

*С Selenide:*
```kotlin
val element = `$`(AppiumBy.id("..."))
element.click()
element.shouldHave(text("Hello"))
```

Разница очевидна. Selenide позволяет сфокусироваться на логике теста, а не на борьбе с фреймворком.
