Вместо громоздких ассертов Selenide предлагает использовать **условия (Conditions)**. Это набор готовых проверок, которые можно применять к элементам.

[[section-should-methods]]
== Методы `shouldBe`, `shouldHave`, `should`

*   `element.shouldBe(condition)`: Проверяет, что элемент соответствует условию (например, `visible`).
*   `element.shouldHave(condition)`: Проверяет, что элемент имеет какое-то свойство (например, `text("Hello")`).
*   `element.should(condition)`: Синоним `shouldBe`.

Как и действия, проверки тоже имеют **встроенные ожидания**. `element.shouldBe(visible)` будет ждать, пока элемент не станет видимым.

[[section-common-conditions]]
== Основные условия

*   `visible`: Элемент видим.
*   `hidden`: Элемент скрыт.
*   `exist`: Элемент существует в DOM (даже если не видим).
*   `text("expected text")`: Элемент имеет точный текст.
*   `exactText("expected text")`: Синоним `text`.
*   `textCaseSensitive("...")`: Текст с учетом регистра.
*   `matchText("regex")`: Текст соответствует регулярному выражению.
*   `attribute("name", "value")`: Элемент имеет атрибут с нужным значением.
*   `enabled`: Элемент активен.
*   `selected`: Элемент выбран (для чекбоксов, радиокнопок).

[[section-example]]
== Пример теста с проверками

```kotlin
import com.codeborne.selenide.Condition.*
import com.codeborne.selenide.Selenide.`$`
import io.appium.java_client.AppiumBy

@Test
fun successfulLogin_opensProductCatalog() {
    `$`(AppiumBy.id("com.example.app:id/username_input")).setValue("standard_user")
    `$`(AppiumBy.id("com.example.app:id/password_input")).setValue("secret_sauce")
    `$`(AppiumBy.id("com.example.app:id/login_button")).click()

    // Проверяем, что заголовок на следующем экране видим и имеет правильный текст
    `$`(AppiumBy.xpath("//*[@text='Products']"))
        .shouldBe(visible)
        .shouldHave(text("Products"))
}
```

Код становится декларативным и очень легко читается.
