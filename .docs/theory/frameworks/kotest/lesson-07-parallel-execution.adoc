В отличие от JUnit 4, где параллелизм достигается в основном за счет внешних инструментов, Kotest имеет мощную и гибкую **встроенную поддержку** параллельного выполнения тестов. Это позволяет значительно сократить время выполнения больших тестовых наборов.

[[section-how-it-works]]
== Как это работает?

Kotest может управлять параллелизмом на двух уровнях:

1.  **Параллельное выполнение спеков (Specs):** Разные тестовые классы (файлы `...Spec.kt`) могут выполняться одновременно в разных потоках. Это самый распространенный и безопасный способ.
2.  **Параллельное выполнение тест-кейсов (Test Cases):** Отдельные тесты (блоки `test { ... }`) внутри одного спека также могут выполняться параллельно. Это требует большей осторожности и потокобезопасных тестов.

[[section-configuration]]
== Настройка через `ProjectConfig`

Управление параллелизмом осуществляется централизованно через объект, унаследованный от `AbstractProjectConfig`. Обычно его размещают в `src/test/kotlin/ProjectConfig.kt`.

```kotlin
import io.kotest.core.config.AbstractProjectConfig
import io.kotest.core.spec.SpecExecutionOrder
import io.kotest.core.test.TestCaseOrder

object ProjectConfig : AbstractProjectConfig() {
    // Главный параметр: количество потоков для выполнения тестов.
    // Значение > 1 включает параллельный запуск.
    // Распространенная практика - использовать количество ядер процессора.
    override val parallelism = Runtime.getRuntime().availableProcessors()

    // Порядок выполнения самих тестовых классов (спеков).
    override val specExecutionOrder = SpecExecutionOrder.Lexicographical

    // Порядок выполнения тестов внутри одного класса.
    // Sequential - последовательно (самый безопасный вариант по умолчанию).
    override val testCaseOrder = TestCaseOrder.Sequential
}
```

=== Ключевые параметры

*   `parallelism`: Устанавливает количество потоков, которые Kotest будет использовать. Если значение равно `1` (или не задано), все тесты будут выполняться последовательно. Любое значение больше `1` включает параллельный режим.

*   `testCaseOrder`: Определяет, как будут выполняться тесты внутри одного файла.
    *   `TestCaseOrder.Sequential`: Тесты выполняются один за другим. Это **безопасный** вариант по умолчанию, даже если `parallelism > 1`.
    *   `TestCaseOrder.Lexicographical` или `Random`: Тесты *внутри одного спека* могут выполняться параллельно, если `parallelism > 1`.

[WARNING]
====
Использование `TestCaseOrder.Random` или `Lexicographical` при `parallelism > 1` требует, чтобы ваши тесты были полностью независимыми и потокобезопасными. Они не должны изменять общие поля в классе спека или другие общие ресурсы без синхронизации. Для большинства случаев достаточно параллельного выполнения спеков с `TestCaseOrder.Sequential`.
====

[[section-summary]]
== Итог

Встроенная поддержка параллелизма в Kotest — это мощный инструмент для ускорения ваших тестов. Простая настройка через `ProjectConfig` позволяет легко активировать и контролировать параллельное выполнение, делая его одной из ключевых особенностей фреймворка.
