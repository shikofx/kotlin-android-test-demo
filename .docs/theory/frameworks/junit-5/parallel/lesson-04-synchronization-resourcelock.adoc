Это самый важный механизм для обеспечения безопасности при параллельном выполнении. Аннотация `@ResourceLock` позволяет декларативно указать, что тест (или тестовый класс) требует эксклюзивного доступа к определенному общему ресурсу.

JUnit 5 гарантирует, что два теста, запрашивающие блокировку одного и того же ресурса, **никогда не будут выполняться одновременно**.

[[section-resourcelock-usage]]
== Использование `@ResourceLock`

Аннотация принимает имя ресурса и, опционально, режим блокировки.

```kotlin
import org.junit.jupiter.api.parallel.ResourceLock
import org.junit.jupiter.api.parallel.Resources

@Test
@ResourceLock(Resources.SYSTEM_PROPERTIES)
fun testThatModifiesSystemProperties() {
    System.setProperty("my.prop", "value1")
    // ...
}
```

[[section-built-in-resources]]
== Встроенные ресурсы

JUnit 5 предоставляет константы для нескольких общих системных ресурсов в классе `org.junit.jupiter.api.parallel.Resources`:

*   `SYSTEM_PROPERTIES`: Блокировка для `System.getProperties()`.
*   `SYSTEM_OUT`: Блокировка для `System.out`.
*   `SYSTEM_ERR`: Блокировка для `System.err`.
*   `LOCALE`: Блокировка для `Locale.getDefault()`.
*   `TIME_ZONE`: Блокировка для `TimeZone.getDefault()`.

[[section-custom-resources]]
== Пользовательские ресурсы

Вы можете определять свои собственные имена ресурсов для блокировки доступа к файлам, базам данных или любым другим общим компонентам.

```kotlin
class FileAccessTest {

    @Test
    @ResourceLock("config.json")
    fun testWritesToConfigFile() {
        // Этот тест эксклюзивно работает с файлом config.json
    }

    @Test
    @ResourceLock("config.json")
    fun testReadsFromConfigFile() {
        // Этот тест тоже работает с config.json и не будет запущен
        // одновременно с testWritesToConfigFile()
    }
}
```

[[section-lock-modes]]
== Режимы блокировки

По умолчанию `@ResourceLock` использует режим `READ_WRITE`. Но можно указать и `READ`.
*   `READ_WRITE`: Эксклюзивный доступ. Никакой другой тест (ни `READ`, ни `READ_WRITE`) не может получить доступ к этому ресурсу.
*   `READ`: "Разделяемый" доступ. Несколько тестов с блокировкой `READ` могут выполняться одновременно. Но они будут ждать, пока завершится тест с блокировкой `READ_WRITE`.

Это полезно, когда у вас есть много тестов, которые только читают из общего ресурса, и лишь несколько, которые его изменяют.
