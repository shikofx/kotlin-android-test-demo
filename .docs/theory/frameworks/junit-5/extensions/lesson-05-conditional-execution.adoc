[[section-what-is-ec]]
== Что такое `ExecutionCondition`?

Этот интерфейс расширения позволяет динамически включать или отключать выполнение тестов (или целых контейнеров/классов) на основе определенных условий.

Он имеет один метод `evaluateExecutionCondition()`, который должен вернуть `ConditionEvaluationResult`.
*   `ConditionEvaluationResult.enabled("Причина")`: Тест будет выполнен.
*   `ConditionEvaluationResult.disabled("Причина")`: Тест будет пропущен.

Встроенные аннотации `@Disabled`, `@EnabledOnOs`, `@DisabledIfEnvironmentVariable` и т.д. реализованы с помощью этого механизма.

[[section-example]]
== Пример: Расширение для запуска тестов только в CI

Давайте создадим расширение, которое будет пропускать тесты, если они не запущены в среде CI (что мы определим по наличию переменной окружения `CI`).

```kotlin
import org.junit.jupiter.api.extension.ConditionEvaluationResult
import org.junit.jupiter.api.extension.ExecutionCondition
import org.junit.jupiter.api.extension.ExtensionContext

class DisabledOnLocalEnvironment : ExecutionCondition {

    override fun evaluateExecutionCondition(context: ExtensionContext): ConditionEvaluationResult {
        val isCi = System.getenv("CI") != null
        return if (isCi) {
            ConditionEvaluationResult.enabled("Test enabled on CI environment")
        } else {
            ConditionEvaluationResult.disabled("Test disabled on local environment")
        }
    }
}

// Создадим свою аннотацию для удобства
@Target(AnnotationTarget.CLASS, AnnotationTarget.FUNCTION)
@Retention(AnnotationRetention.RUNTIME)
@ExtendWith(DisabledOnLocalEnvironment::class)
annotation class EnabledOnCi

// Используем в тесте
class MyCiTest {

    @Test
    @EnabledOnCi
    fun `this test runs only on CI`() {
        // ...
    }
}
```

Если вы запустите этот тест локально, он будет пропущен. Если вы запустите его в GitLab CI (где переменная `CI` обычно установлена), он будет выполнен.
