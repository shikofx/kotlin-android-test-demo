== Настройка

Для начала добавьте зависимость Kakao в ваш файл `build.gradle.kts`:

```kotlin
androidTestImplementation("io.github.kakaocup:kakao:3.0.0") // Уточните последнюю версию
```

[[section-creating-screen]]
== Создание класса Screen

Паттерн Page Object (в Kakao он называется **Screen**) — это основа структурированных UI-тестов. Давайте создадим `Screen` для экрана логина, который мы тестировали с помощью Espresso.

Каждый `Screen` наследуется от класса `Screen<YourScreenClass>`. Внутри него мы объявляем все интерактивные элементы UI.

```kotlin
import com.agoda.kakao.screen.Screen
import com.agoda.kakao.edit.KEditText
import com.agoda.kakao.text.KButton
import com.example.app.R // Замените на ваш пакет

class LoginScreen : Screen<LoginScreen>() {

    // Поле для ввода имени пользователя
    val usernameField: KEditText = KEditText { withId(R.id.username_input) }

    // Поле для ввода пароля
    val passwordField: KEditText = KEditText { withId(R.id.password_input) }

    // Кнопка "Войти"
    val loginButton: KButton = KButton { withId(R.id.login_button) }
}
```

=== Что здесь происходит?

*   `class LoginScreen : Screen<LoginScreen>()`: Мы создаем класс, представляющий экран логина.
*   `val usernameField: KEditText = KEditText { ... }`: Мы объявляем свойство `usernameField` типа `KEditText`. В лямбда-выражении `{ withId(R.id.username_input) }` мы передаем обычный `ViewMatcher` из Espresso. Kakao будет использовать его для поиска элемента, когда мы обратимся к этому свойству.
*   `KEditText`, `KButton` — это готовые классы Kakao для соответствующих `View`. Они уже содержат все необходимые `ViewAction` и `ViewAssertion`.

Теперь у нас есть полное описание экрана логина в одном месте. Если ID кнопки изменится, нам нужно будет исправить его только здесь. В следующем уроке мы увидим, как использовать этот `Screen` в тестах.
