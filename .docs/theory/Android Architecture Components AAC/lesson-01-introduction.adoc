[[section-what-is-aac-testing]]
== Что такое тестирование Android Architecture Components?

**Android Architecture Components (AAC)** — это набор библиотек, который помогает создавать надежные, тестируемые и поддерживаемые приложения. Ключевые компоненты, такие как `ViewModel`, `LiveData` и `Room`, составляют основу современной Android-архитектуры.

Тестирование этих компонентов отличается от классического тестирования UI или простой бизнес-логики, поскольку они тесно связаны с жизненным циклом Android и часто работают асинхronно.

[[section-why-test-aac]]
== Зачем это нужно?

*   **Надежность:** `ViewModel` содержит логику отображения. Тесты гарантируют, что UI будет правильно реагировать на изменения данных.
*   **Корректность данных:** Тесты для `LiveData` и `Flow` проверяют, что преобразования данных работают как ожидается.
*   **Изоляция:** Мы можем тестировать `ViewModel` отдельно от UI (`Activity`/`Fragment`), что делает тесты быстрыми и стабильными.

[[section-tools]]
== Инструменты, которые мы будем использовать

1.  **JUnit 5:** Основной фреймворк для написания тестов.
2.  **Mockito/MockK:** Для создания моков (заглушек) зависимостей, таких как репозитории.
3.  **`InstantTaskExecutorRule` / `InstantExecutorExtension`:** Для синхронного выполнения операций с `LiveData`.
4.  **`kotlinx-coroutines-test`:** Библиотека от JetBrains для тестирования корутин. Предоставляет `TestCoroutineDispatcher` и `runTest`.
5.  **Turbine:** Популярная библиотека для простого и декларативного тестирования `Flow`.

В следующих уроках мы подробно рассмотрим тестирование каждого из этих компонентов.
