= Урок 4: Проверка исходящих запросов (URL, метод, заголовки)

Одна из ключевых задач нашего тест-плана — убедиться, что `Network.java` формирует правильные запросы. `MockEngine` позволяет легко это проверить.

Объект `request` внутри `handler`-а `MockEngine` содержит всю информацию об исходящем запросе.

== Пример: Проверка URL и заголовков

Давайте напишем тест, который проверяет, что `Network.java` правильно формирует GET-запрос и добавляет заголовки `User-Agent` и `X-Trace-ID`.

[source,kotlin]
----
import io.ktor.client.HttpClient
import io.ktor.client.engine.mock.*
import io.ktor.client.request.*
import io.ktor.http.*
import kotlinx.coroutines.runBlocking
import org.junit.jupiter.api.Assertions.assertEquals
import org.junit.jupiter.api.Test
import java.util.UUID

class NetworkTest {
    @Test
    fun `request should have correct path and headers`() = runBlocking {
        val mockEngine = MockEngine { request ->
            // Проверяем URL
            assertEquals("/v1/products", request.url.encodedPath)

            // Проверяем HTTP-метод
            assertEquals(HttpMethod.Get, request.method)

            // Проверяем заголовки
            assertEquals("my-app/1.0", request.headers["User-Agent"])
            assert(request.headers.contains("X-Trace-ID"))

            respond("{}", HttpStatusCode.OK, headersOf(HttpHeaders.ContentType, "application/json"))
        }

        val client = HttpClient(mockEngine)
        val network = Network(client) // <1>

        network.fetchProducts() // <2>
    }
}
----
<1> Создаем экземпляр нашего класса с мок-клиентом.
<2> Вызываем тестируемый метод, который делает GET-запрос.

В этом тесте мы делаем проверки прямо внутри `handler`-а. Если `assertEquals` или другая проверка провалится, тест упадет, и мы точно будем знать, что запрос был сформирован неверно.
