= Урок 2: Настройка и базовый тест

На этом уроке мы добавим необходимые зависимости и напишем первый тест для `Network.java`, используя `ktor-client-mock`.

== Шаг 1: Добавление зависимости

Откройте файл `build.gradle` вашего модуля `app` и добавьте зависимость `ktor-client-mock` в блок `dependencies`. Убедитесь, что версия совпадает с другими вашими Ktor-зависимостями.

[source,groovy]
----
dependencies {
    // ... другие зависимости

    // Ktor
    def ktor_version = "2.3.10" // Используйте актуальную версию
    implementation "io.ktor:ktor-client-core:$ktor_version"
    implementation "io.ktor:ktor-client-cio:$ktor_version"
    testImplementation "io.ktor:ktor-client-mock:$ktor_version" // <1>
}
----
<1> Добавляем зависимость для тестов.

== Шаг 2: Создание базового теста

Предположим, наш `Network.java` использует `HttpClient` для выполнения запросов. Мы создадим тест, который проверяет простой GET-запрос.

Основная идея — создать `HttpClient` со специальным движком `MockEngine`. В `MockEngine` мы передаем лямбда-выражение (`handler`), которое определяет, какой ответ (`respond`) вернуть на конкретный запрос.

[source,kotlin]
----
import io.ktor.client.*
import io.ktor.client.engine.mock.*
import io.ktor.http.*

// ...

val mockEngine = MockEngine { request ->
    respond(
        content = "{\"status\":\"OK\"}",
        status = HttpStatusCode.OK,
        headers = headersOf(HttpHeaders.ContentType, "application/json")
    )
}

val client = HttpClient(mockEngine)

// Теперь этот 'client' можно передать в наш Network.java для теста
----

В этом примере мы создали движок, который на любой запрос возвращает успешный JSON-ответ.

*Важно:* Чтобы этот тест заработал, наш класс `Network` должен уметь принимать `HttpClient` извне (через конструктор). Этому посвящен следующий урок.
