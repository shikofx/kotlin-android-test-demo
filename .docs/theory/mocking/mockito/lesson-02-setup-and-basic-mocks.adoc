== Настройка

Для работы с Mockito в Kotlin-проекте нам понадобятся три зависимости:

```kotlin
// build.gradle.kts (app)

dependencies {
    // Ядро Mockito
    testImplementation("org.mockito:mockito-core:5.4.0")

    // Адаптер для удобной работы с Mockito в Kotlin
    testImplementation("org.mockito.kotlin:mockito-kotlin:5.1.0")

    // Для мокирования final классов и методов (необходимо для Kotlin)
    testImplementation("org.mockito:mockito-inline:5.2.0")
}
```

*   `mockito-core`: Основная библиотека.
*   `mockito-kotlin`: Библиотека-адаптер, которая предоставляет удобные функции-обертки (`whenever`, `any`, `verify`) и решает проблемы с `nullability`.
*   `mockito-inline`: Позволяет Mockito мокировать `final` классы и методы, что критически важно для Kotlin, где классы по умолчанию `final`.

== Создание моков

Самый удобный способ создавать моки — использовать аннотацию `@Mock` и расширение JUnit 5 `MockitoExtension`.

```kotlin
import org.junit.jupiter.api.Test
import org.junit.jupiter.api.extension.ExtendWith
import org.mockito.Mock
import org.mockito.junit.jupiter.MockitoExtension

@ExtendWith(MockitoExtension::class)
class MyTest {

    // MockitoExtension автоматически создаст мок для этого поля
    @Mock
    private lateinit var repository: DatabaseRepository

    @Test
    fun `test something`() {
        // Здесь 'repository' уже является инициализированным мок-объектом
        // ...
    }
}
```

`MockitoExtension` выполняет ту же роль, что и `MockitoAnnotations.initMocks(this)` в старых версиях Mockito, но делает это более элегантно и в стиле JUnit 5.
