**GitLab CI/CD** — это мощный инструмент, встроенный в GitLab, который позволяет автоматизировать все этапы вашего пайплайна.

[[section-gitlab-ci-yml]]
== Файл `.gitlab-ci.yml`

Вся конфигурация пайплайна описывается в одном файле — `.gitlab-ci.yml`, который должен находиться в корне вашего репозитория.

=== Ключевые концепции:

*   **`stages`**: Определяет порядок выполнения этапов. Задачи (`jobs`) одного этапа выполняются параллельно, а сами этапы — последовательно.
*   **`job`**: Задача, которая выполняется на "раннере". Например, `build_app` или `run_unit_tests`.
*   **`image`**: Указывает Docker-образ, в котором будет выполняться задача. Для Android-сборки это обычно образ с установленными Java и Android SDK.
*   **`script`**: Основная часть задачи. Содержит shell-команды, которые нужно выполнить.
*   **`artifacts`**: Позволяет сохранять файлы (например, собранный APK или отчеты) после выполнения задачи и передавать их на следующие этапы.
*   **`runner`**: Машина (физическая или виртуальная), на которой фактически выполняются задачи.

[[section-example]]
== Пример простого пайплайна

Давайте создадим `.gitlab-ci.yml`, который просто собирает наше приложение.

```yaml
# .gitlab-ci.yml

stages:
  - build

build_job:
  stage: build
  image: openjdk:17-jdk # Используем образ с Java 17

  before_script:
    # Устанавливаем Android SDK (в реальном проекте лучше использовать готовый Docker-образ)
    - apt-get update && apt-get install -y android-sdk
    - export ANDROID_HOME=/usr/lib/android-sdk

  script:
    - echo "Building the app..."
    - chmod +x ./gradlew
    - ./gradlew assembleDebug

  artifacts:
    paths:
      - app/build/outputs/apk/debug/app-debug.apk
```

Когда вы запушите этот файл в репозиторий, GitLab автоматически запустит пайплайн, который выполнит задачу `build_job`. После успешного выполнения вы сможете скачать `app-debug.apk` из артефактов задачи.
