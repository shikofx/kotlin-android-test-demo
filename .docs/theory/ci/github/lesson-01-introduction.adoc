**GitHub Actions** — это платформа для автоматизации рабочих процессов непосредственно в вашем репозитории GitHub. Она позволяет создавать CI/CD пайплайны, которые автоматически собирают, тестируют и развертывают ваш код.

== Ключевые концепции

*   **Workflow (Пайплайн):** Это главный конфигурационный YAML-файл, который описывает весь автоматизированный процесс. Он находится в директории `.github/workflows/`. В нашем проекте это `ci.yml`.

*   **Event (Событие):** Это триггер, который запускает workflow. Например, `push` в ветку, создание `pull_request` или ручной запуск (`workflow_dispatch`).

[source,yaml]
----
on:
  push:
    branches: [ main ]
  pull_request:
----

*   **Job (Задание):** Workflow состоит из одного или нескольких заданий (`jobs`). Каждое задание выполняется на отдельной виртуальной машине (раннере) и состоит из шагов. Задания могут выполняться параллельно или последовательно (с помощью `needs`).

*   **Step (Шаг):** Это отдельная задача внутри задания. Шаг может быть командой в терминале (`run`) или готовым действием (`uses`).

*   **Action (Действие):** Это переиспользуемый блок кода, который выполняет сложную, но часто повторяющуюся задачу (например, `actions/checkout@v4` для клонирования репозитория или `actions/setup-java@v4` для установки Java).

*   **Runner (Исполнитель):** Это виртуальная машина (Linux, Windows или macOS), на которой выполняются ваши задания. GitHub предоставляет стандартные раннеры, но можно настроить и собственные.

*   **Artifact (Артефакт):** Это файлы (например, APK, отчеты о тестах), которые создаются во время выполнения задания. Их можно сохранить и передать в другие задания.

В следующих уроках мы создадим наш первый workflow и последовательно добавим в него все необходимые шаги.
