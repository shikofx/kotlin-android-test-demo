Запуск UI-тестов на эмуляторах в CI может быть медленным и нестабильным. Профессиональный подход — использовать облачные фермы реальных устройств, такие как BrowserStack.

== Настройка секретов

Для доступа к BrowserStack нужны учетные данные. Их нельзя хранить в коде. Вместо этого мы используем **секреты** GitHub.

1.  Перейдите в `Settings` -> `Secrets and variables` -> `Actions` вашего репозитория.
2.  Создайте два секрета:
*   `BROWSERSTACK_USERNAME`: ваш логин в BrowserStack.
*   `BROWSERSTACK_ACCESS_KEY`: ваш ключ доступа.

== Workflow для UI-тестов

Создадим workflow, который будет запускать тесты на BrowserStack. Пример для интеграционных тестов: `.github/workflows/integration-ui-test-flow.yml`.

[source,yaml]
----
name: Integration UI Test Flow

on:
  workflow_call:
    secrets:
      BROWSERSTACK_USERNAME:
        required: true
      BROWSERSTACK_ACCESS_KEY:
        required: true

jobs:
  run_integration_ui_tests:
    runs-on: ubuntu-latest
    steps:
      # ... шаги checkout, setup-android, cache-gradle ...

      - name: Build App and Test APKs
        run: |
          ./gradlew assembleDebug
          ./gradlew assembleDebugAndroidTest

      - name: Run Integration UI Tests on BrowserStack
        env:
          BROWSERSTACK_USERNAME: ${{ secrets.BROWSERSTACK_USERNAME }}
          BROWSERSTACK_ACCESS_KEY: ${{ secrets.BROWSERSTACK_ACCESS_KEY }}
        run: |
          # Установка утилиты BrowserStack и jq для парсинга JSON
          npm install -g browserstack-cli
          sudo apt-get install jq -y

          # Загрузка APK приложения
          APP_URL=$(browserstack-cli app-automate app upload --path app/build/outputs/apk/debug/app-debug.apk | jq -r '.app_url')
          # Загрузка тестового APK
          TEST_URL=$(browserstack-cli app-automate app upload --path app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk | jq -r '.app_url')
          # Запуск тестов
          browserstack-cli app-automate espresso --app $APP_URL --test-suite $TEST_URL --devices "Google Pixel 8-14.0" --annotation "by.pda.demoapp.ui.espresso.Tag:integration-ui"

      # ... шаг upload-artifact для отчетов ...
----
*   `on.workflow_call.secrets`: Объявляем, что этот workflow ожидает получить секреты.
*   `env`: Передаем секреты как переменные окружения для `browserstack-cli`.
*   `run`: Скрипт выполняет три действия: собирает APK, загружает их на BrowserStack и запускает тесты с фильтрацией по тегу `integration-ui`.

Аналогичный workflow (`component-ui-test-flow.yml`) создается для тестов с тегом `component-ui`.

== Обновление `ci.yml`

Добавим вызовы UI-тестов в главный файл, передав в них секреты.

[source,yaml]
----
  component_ui_testing:
    name: Component UI Test
    needs: [testing]
    uses: ./.github/workflows/component-ui-test-flow.yml
    secrets:
      BROWSERSTACK_USERNAME: ${{ secrets.BROWSERSTACK_USERNAME }}
      BROWSERSTACK_ACCESS_KEY: ${{ secrets.BROWSERSTACK_ACCESS_KEY }}

  integration_ui_testing:
    # ... аналогично для integration-ui ...
----
