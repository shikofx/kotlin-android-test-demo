== Что такое CI/CD?

**CI/CD** — это практика автоматизации этапов разработки программного обеспечения.

*   **Непрерывная Интеграция (Continuous Integration, CI):** Это практика, при которой разработчики часто сливают свои изменения в центральный репозиторий. После каждого слияния автоматически запускается сборка и тесты, что позволяет быстро обнаруживать проблемы интеграции.

*   **Непрерывная Доставка (Continuous Delivery, CD):** Это расширение CI. Каждый раз, когда сборка успешно проходит все тесты, она автоматически развертывается в тестовое или пред-продакшн окружение.

== Типичный CI/CD пайплайн для мобильного приложения

Для мобильного приложения автоматизированный пайплайн обычно включает следующие этапы (stages):

1.  **Сборка (Build):** Компиляция кода и сборка APK или AAB файла.
2.  **Анализ Качества (Code Quality):**
    *   Запуск статических анализаторов (Lint, Detekt) для поиска потенциальных ошибок и нарушений стиля.
    *   Измерение покрытия кода тестами (Code Coverage).
3.  **Тестирование (Test):**
    *   Запуск Unit-тестов (быстрые, на JVM).
    *   Запуск Инструментальных/UI-тестов (на эмуляторе или реальном устройстве).
4.  **Отчетность (Report):** Генерация и публикация отчетов о результатах тестов (например, с помощью Allure).
5.  **Развертывание (Deploy):** Загрузка артефакта (APK) в хранилище или на платформу для тестировщиков (например, Firebase App Distribution).

В этом курсе мы рассмотрим, как реализовать такой пайплайн с помощью GitLab CI.
