Автоматическая проверка качества кода — важный шаг CI, который помогает поддерживать кодовую базу в хорошем состоянии.

[[section-static-analysis]]
== Статический анализ

Статические анализаторы проверяют ваш код без его выполнения, находя потенциальные ошибки, уязвимости и нарушения стиля.

*   **Lint:** Встроенный в Android Gradle Plugin анализатор. Находит проблемы, специфичные для Android.
*   **Detekt/Ktlint:** Популярные анализаторы для Kotlin. `Detekt` более мощный и настраиваемый, `Ktlint` — простой и сфокусированный на форматировании.

=== Интеграция в GitLab CI

Вы можете добавить задачу, которая запускает эти анализаторы.

```yaml
code_analysis_job:
  stage: analyze
  script:
    - ./gradlew lintDebug  # Запуск Lint
    - ./gradlew detekt     # Запуск Detekt (требует плагин)
```

[[section-code-coverage]]
== Покрытие кода тестами (Code Coverage)

Покрытие кода — это метрика, которая показывает, какой процент вашего кода выполняется во время тестов. Это помогает находить не протестированные участки.

**JaCoCo** (Java Code Coverage) — это стандартный инструмент для измерения покрытия в JVM-мире.

=== Настройка и запуск

1.  **Подключите плагин JaCoCo** в `build.gradle.kts`.
2.  **Создайте Gradle-задачу**, которая объединяет результаты покрытия от unit- и инструментальных тестов.

=== Интеграция в GitLab CI

```yaml
coverage_job:
  stage: test
  script:
    - ./gradlew jacocoTestReport # Запускаем задачу генерации отчета
  artifacts:
    paths:
      - app/build/reports/jacoco/ # Сохраняем HTML-отчет
```

GitLab также умеет парсить вывод о покрытии и отображать его в UI. Для этого нужно настроить регулярное выражение в настройках CI/CD вашего проекта.
