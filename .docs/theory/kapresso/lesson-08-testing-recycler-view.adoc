Тестирование `RecyclerView` — одна из самых частых и сложных задач в UI-автоматизации на Android. Kaspresso, как и Kakao, предоставляет мощные инструменты для работы со списками, значительно упрощая эту задачу и делая тесты более стабильными.

[[section-krecyclerview]]
== KRecyclerView и KRecyclerItem

Kaspresso использует те же концепции `KRecyclerView` и `KRecyclerItem`, что и Kakao, но с дополнительными преимуществами Kaspresso (повторные попытки, улучшенная синхронизация).

Сначала определим `KScreen` для экрана каталога продуктов, который содержит `RecyclerView`.

```kotlin
import android.view.View
import com.agoda.kakao.recycler.KRecyclerItem
import com.agoda.kakao.recycler.KRecyclerView
import com.agoda.kakao.text.KTextView
import com.agoda.kakao.text.KButton
import com.example.app.R
import com.kaspersky.kaspresso.screens.KScreen
import org.hamcrest.Matcher
import androidx.test.espresso.matcher.ViewMatchers.*

object ProductCatalogScreen : KScreen<ProductCatalogScreen>() {

    override val layoutId: Int? = R.layout.fragment_product_catalog
    override val viewClass: Class<*>? = ProductCatalogFragment::class.java

    val productList = KRecyclerView(
        builder = { withId(R.id.product_list) },
        itemTypeBuilder = { itemType(::ProductItem) }
    )

    // Описываем, как выглядит один элемент списка
    class ProductItem(parent: Matcher<View>) : KRecyclerItem<ProductItem>(parent) {
        val name = KTextView(parent) { withId(R.id.product_name) }
        val price = KTextView(parent) { withId(R.id.product_price) }
        val addToCartButton = KButton(parent) { withId(R.id.add_to_cart_button) }
    }
}
```

[[section-testing-recyclerview-example]]
== Примеры тестов с KRecyclerView

Теперь мы можем легко взаимодействовать с элементами списка, используя мощный DSL Kaspresso.

```kotlin
import com.kaspersky.kaspresso.testcases.api.testcase.TestCase
import com.example.app.ui.product_catalog.ProductCatalogActivity // Ваша Activity, содержащая фрагмент
import org.junit.Rule
import org.junit.Test
import androidx.test.ext.junit.rules.ActivityScenarioRule

class ProductCatalogTest : TestCase() {

    @get:Rule
    val activityRule = ActivityScenarioRule(ProductCatalogActivity::class.java)

    @Test
    fun firstProduct_hasCorrectNameAndCanBeAddedToCart() = run {
        ProductCatalogScreen {
            productList {
                // Проверяем первый элемент
                firstChild<ProductItem> {
                    name.hasText("Sauce Labs Backpack")
                    price.hasText("$29.99") // Пример, если цена отображается как строка
                    addToCartButton.isDisplayed()
                    addToCartButton.click()
                }

                // Прокручиваем до элемента с определенным текстом и кликаем на него
                childWith<ProductItem> { withDescendant(withText("Sauce Labs Bike Light")) } perform {
                    click()
                }

                // Проверяем элемент на конкретной позиции
                childAt<ProductItem>(2) {
                    name.hasText("Sauce Labs Bolt T-Shirt")
                }
            }
        }
    }
}
```

=== Что здесь происходит?

*   `productList { ... }`: Внутри этого блока мы работаем с нашим `RecyclerView`.
*   `firstChild<ProductItem> { ... }`: Позволяет получить первый видимый элемент списка и выполнить над ним действия или проверки.
*   `childWith<ProductItem> { withDescendant(withText("...")) } perform { click() }`: Это очень мощный способ найти элемент списка по содержимому (например, по тексту внутри одного из его дочерних View), прокрутить до него, если он не виден, и выполнить действие.
*   `childAt<ProductItem>(2) { ... }`: Позволяет получить элемент списка по его позиции.

Kaspresso автоматически обрабатывает прокрутку списка, если элемент не виден на экране, что избавляет от необходимости вручную вызывать `RecyclerViewActions.scrollTo()`. Это значительно повышает стабильность тестов для списков.
