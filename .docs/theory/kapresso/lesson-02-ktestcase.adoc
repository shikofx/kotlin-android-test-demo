== KTestCase: Точка входа в Kaspresso

В Kaspresso каждый тестовый класс должен наследоваться от `KTestCase`. Это не просто базовый класс, а ключевой компонент, который является точкой входа во всю инфраструктуру фреймворка.

В отличие от стандартного подхода с `@RunWith(AndroidJUnit4::class)`, `KTestCase` берет на себя всю "магию" настройки и управления жизненным циклом теста.

[[section-ktestcase-responsibilities]]
== За что отвечает KTestCase?

1.  **Инициализация Kaspresso:** `KTestCase` создает и настраивает экземпляр `Kaspresso`, который управляет всеми действиями, проверками и механизмами повторных попыток.
2.  **Управление жизненным циклом:** Предоставляет удобные хуки (`before`, `after`) для подготовки и очистки тестового окружения.
3.  **Структурирование тестов:** Предлагает методы `run` и `step` для написания чистых и структурированных тестовых сценариев.
4.  **Доступ к `device` API:** Дает прямой доступ к объекту `device`, через который можно управлять разрешениями, выполнять ADB-команды, делать скриншоты и т.д.

[[section-ktestcase-structure]]
== Структура теста с KTestCase

Рассмотрим типичную структуру тестового класса, использующего `KTestCase`.

```kotlin
import androidx.test.ext.junit.rules.ActivityScenarioRule
import com.kaspersky.kaspresso.testcases.api.testcase.TestCase
import com.example.app.ui.login.LoginActivity
import org.junit.Rule
import org.junit.Test

class LoginTest : TestCase() {

    // 1. Правило для запуска Activity
    @get:Rule
    val activityRule = ActivityScenarioRule(LoginActivity::class.java)

    // 2. Подготовка перед тестом (опционально)
    override fun before() {
        super.before()
        // Например, очистка SharedPreferences или базы данных
    }

    // 3. Сам тест, обернутый в `run`
    @Test
    fun loginTest() = run {
        step("Выполнить вход с валидными данными") {
            // Логика теста
        }
    }

    // 4. Очистка после теста (опционально)
    override fun after() {
        super.after()
        // Например, выход из системы
    }
}
```

*   **`@get:Rule`**: Стандартный способ JUnit для управления `Activity`. Kaspresso полностью совместим с `ActivityScenarioRule`.
*   **`before()` и `after()`**: Методы `KTestCase`, которые выполняются до и после каждого теста. Они идеально подходят для подготовки и очистки состояния приложения, обеспечивая изоляцию тестов.
*   **`run { ... }`**: Оборачивание тела теста в `run` — это идиома Kaspresso. Она гарантирует, что все действия внутри будут выполняться под контролем Kaspresso, с его логированием, повторными попытками и обработкой ошибок.
*   **`step("...") { ... }`**: Позволяет разбивать тест на логические шаги, которые будут красиво отображены в отчетах (например, Allure Report).
