Во многих существующих проектах для асинхронной работы с Room используется RxJava. Тестирование DAO, возвращающих `Flowable`, `Single` или `Maybe`, также требует специального подхода.

[[section-setup-rxjava]]
== Настройка

Убедитесь, что у вас есть зависимости для RxJava и интеграции Room с RxJava.

```kotlin
// build.gradle.kts (app)
dependencies {
    // ...
    implementation("androidx.room:room-rxjava3:2.5.2")
    implementation("io.reactivex.rxjava3:rxjava:3.1.6")
    implementation("io.reactivex.rxjava3:rxandroid:3.0.2")
}
```

[[section-writing-rxjava-test]]
== Написание теста для RxJava

Основная идея тестирования RxJava-стримов — подписаться на них и использовать специальные тестовые подписчики (`TestObserver` или `TestSubscriber`), которые предоставляют удобные методы для проверок.

=== Пример теста

Предположим, наш `AppDao` имеет метод, возвращающий `Flowable`:

```kotlin
// В AppDao
@Query("SELECT * FROM Product")
fun getAllProductsRx(): Flowable<List<Product>>
```

Тест для этого метода будет выглядеть так:

```kotlin
import org.junit.jupiter.api.Test

class AppDaoRxJavaTest : BaseDaoTest() {

    @Test
    fun `getAllProductsRx should return products from db`() {
        // 1. Подготовка: Вставляем тестовый продукт
        val product = Product(1, "Rx Product", 25.0, 1)
        appDao.insertProduct(product)

        // 2. Действие и Проверка:
        appDao.getAllProductsRx()
            .test() // Создаем TestSubscriber и подписываемся
            .awaitCount(1) // Ждем, пока не придет 1 элемент
            .assertValue { productList -> productList.contains(product) } // Проверяем значение
            .assertNoErrors() // Проверяем, что не было ошибок
    }
}
```

=== Что здесь происходит?

*   **`.test()`**: Этот метод из RxJava превращает `Flowable` (или `Single`, `Observable` и т.д.) в `TestSubscriber`. Этот подписчик немедленно подписывается на источник и начинает получать данные.
*   **`.awaitCount(1)`**: Заставляет тестовый поток ждать, пока не будет получен как минимум один элемент. Это решает проблему асинхронности.
*   **`.assertValue { ... }`**: Выполняет проверку (ассерт) над полученным значением. Лямбда должна вернуть `true`, если проверка прошла.
*   **`.assertNoErrors()`**: Убеждается, что стрим не завершился с ошибкой.

`TestSubscriber` предоставляет множество других полезных методов (`assertComplete()`, `assertValueCount()`, `assertNotComplete()`), которые делают тестирование RxJava-цепочек очень удобным и декларативным.
