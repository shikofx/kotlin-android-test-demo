[[section-gradle-dependencies]]
== Gradle Зависимости

Для начала, убедитесь, что в вашем файле `build.gradle` (модуля `app`) добавлены необходимые зависимости для тестирования Room. Интеграционные тесты запускаются в Android-среде, поэтому мы используем `androidTestImplementation`.

```gradle
dependencies {
    // JUnit 5
    androidTestImplementation 'org.junit.jupiter:junit-jupiter-api:5.10.0'
    androidTestRuntimeOnly 'org.junit.jupiter:junit-jupiter-engine:5.10.0'

    // AndroidX Test Core (для ApplicationProvider)
    androidTestImplementation 'androidx.test:core:1.5.0'
    androidTestImplementation 'androidx.test.ext:junit:1.1.5' // Для JUnit 4-style runner, но полезно для контекста
    androidTestImplementation 'androidx.test:runner:1.5.2'

    // Room Testing
    androidTestImplementation 'androidx.room:room-testing:2.5.2'

    // Google Truth (для более читаемых ассертов)
    androidTestImplementation 'com.google.truth:truth:1.1.5'

    // LiveData testing (если используете LiveData в DAO)
    androidTestImplementation 'androidx.arch.core:core-testing:2.2.0'
}
```

[[section-in-memory-database]]
== Создание In-Memory Базы Данных для Тестов

Для интеграционных тестов Room DAO мы будем использовать in-memory базу данных. Это означает, что база данных будет существовать только в оперативной памяти во время выполнения тестов и будет полностью очищаться после каждого тестового прогона. Это обеспечивает изоляцию тестов и высокую скорость выполнения.

Создадим базовый класс для наших DAO-тестов, который будет отвечать за инициализацию и очистку базы данных.

```java
// d:/t366/code/sdet-practice/kotlin-android-test-demo/app/src/androidTest/java/com/example/app/data/BaseDaoTest.java
package com.example.app.data; // Замените на ваш пакет

import androidx.room.Room;
import android.content.Context;
import androidx.test.core.app.ApplicationProvider;
import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;

public abstract class BaseDaoTest {

    protected AppDatabase database; // Ваша RoomDatabase
    protected AppDao appDao;       // Ваш DAO

    @BeforeEach
    public void setup() {
        Context context = ApplicationProvider.getApplicationContext();
        // Создаем in-memory базу данных для тестов
        database = Room.inMemoryDatabaseBuilder(context, AppDatabase.class)
                .allowMainThreadQueries() // Разрешаем запросы в основном потоке для простоты тестирования
                .build();
        appDao = database.appDao();
    }

    @AfterEach
    public void tearDown() {
        // Закрываем базу данных после каждого теста, чтобы обеспечить изоляцию
        database.close();
    }
}
```

=== Объяснение кода:

*   `@BeforeEach`: Эта аннотация JUnit 5 указывает, что метод `setup()` будет выполняться перед *каждым* тестовым методом в классе.
*   `ApplicationProvider.getApplicationContext()`: Предоставляет контекст приложения, необходимый для инициализации Room.
*   `Room.inMemoryDatabaseBuilder(context, AppDatabase.class)`: Создает экземпляр RoomDatabase, который будет работать полностью в памяти. Это ключевой момент для быстрых и изолированных интеграционных тестов.
*   `.allowMainThreadQueries()`: По умолчанию Room запрещает выполнение запросов к БД в основном потоке, чтобы предотвратить блокировку UI. Однако в тестах, для упрощения и синхронности, часто разрешают эту опцию. *В реальном приложении никогда не используйте эту опцию!*
*   `appDao = database.appDao()`: Получаем экземпляр вашего Data Access Object (DAO), который мы будем тестировать.
*   `@AfterEach`: Этот метод `tearDown()` выполняется после *каждого* тестового метода.
*   `database.close()`: Очень важно закрывать базу данных после каждого теста. Это гарантирует, что каждый тест начинается с чистой, пустой базы данных, предотвращая "грязные" тесты и зависимости между ними.
