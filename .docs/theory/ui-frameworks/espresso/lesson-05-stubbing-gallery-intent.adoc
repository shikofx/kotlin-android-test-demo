Один из самых частых сценариев использования стабинга — имитация выбора файла из галереи или изображения с камеры. В тестах мы не хотим открывать реальную галерею. Вместо этого мы можем "застабать" (от англ. stub) этот `Intent` — перехватить его и вернуть заранее подготовленный результат, как если бы пользователь действительно выбрал изображение.

Для этого используется `Intents.intending()`.

== Реализация

[source,kotlin]
----
@Test
fun pickingImage_displaysItInImageView() {
    // 1. Создаем "фейковый" результат, как будто мы выбрали картинку
    val resultData = Intent()
    val imageUri = Uri.parse("content://fake/image.jpg")
    resultData.data = imageUri
    val result = Instrumentation.ActivityResult(Activity.RESULT_OK, resultData)

    // 2. Указываем Espresso: "когда будет запущен Intent на выбор контента,
    // не открывай галерею, а верни наш фейковый результат"
    intending(hasAction(Intent.ACTION_PICK)).respondWith(result)

    // 3. Кликаем на кнопку, которая запускает выбор изображения
    onView(withId(R.id.pick_image_button)).perform(click())

    // 4. Проверяем, что в нашем ImageView появилась "выбранная" картинка
    onView(withId(R.id.image_view)).check(matches(withImageUri(imageUri))) // withImageUri - кастомный матчер
}
----

*   `Instrumentation.ActivityResult`: Класс для создания "фейкового" результата, который вернет `Activity`. Мы указываем код результата (`Activity.RESULT_OK`) и данные (`Intent` с URI изображения).
*   `intending()`: Устанавливает правило перехвата для `Intent`'ов, соответствующих матчеру (в данном случае, `hasAction(Intent.ACTION_PICK)`).
*   `respondWith()`: Указывает, какой результат нужно вернуть при перехвате.
