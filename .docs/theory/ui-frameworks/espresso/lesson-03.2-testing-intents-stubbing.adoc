== Что такое Стабинг (Stubbing)?

**Стабинг** (от англ. stub — "заглушка") — это техника в тестировании, при которой реальный компонент системы заменяется на "заглушку". Эта заглушка имитирует поведение реального компонента, но возвращает заранее определенные, предсказуемые ответы.

В контексте Android-тестирования это особенно полезно, когда ваше приложение взаимодействует с внешними компонентами, такими как:

*   Другие приложения (камера, галерея, контакты).
*   Системные диалоги (выбор файла, запрос разрешений).

Вместо того чтобы запускать реальную камеру в UI-тесте, мы можем "застабать" этот вызов и сразу вернуть результат, как будто пользователь сделал фотографию.

== API для стабинга Intent'ов

В `espresso-intents` за стабинг отвечает метод `intending()`. Его задача — перехватить исходящий `Intent`, который соответствует определенному условию, и немедленно вернуть заранее подготовленный результат.

*   `intending(Matcher<Intent> matcher)`: Устанавливает правило перехвата. Это "условие", при котором сработает заглушка. Например, `intending(hasAction(Intent.ACTION_VIEW))`.

*   `.respondWith(Instrumentation.ActivityResult result)`: Указывает, какой именно результат нужно вернуть, когда `Intent` будет перехвачен.

*   `Instrumentation.ActivityResult(int resultCode, Intent resultData)`: Класс для создания "фейкового" результата.
**   `resultCode`: Код результата, который получит ваша `Activity` в `onActivityResult()` (например, `Activity.RESULT_OK` или `Activity.RESULT_CANCELED`).
**   `resultData`: `Intent`, который содержит "возвращенные" данные (например, URI выбранного изображения).

== Пример: Обработка отсутствия браузера

Этот пример демонстрирует, как с помощью стабинга можно проверить обработку ошибок. Мы имитируем ситуацию, когда `Intent` не может быть обработан (например, на устройстве нет браузера), и проверяем, что приложение корректно информирует пользователя, показывая `Toast`-сообщение.

[source,kotlin]
----
@Test
fun browserIsNotFound() {
    // 1. Создаем результат, имитирующий отмену действия пользователем
    // или невозможность системы обработать Intent.
    val result = Instrumentation.ActivityResult(Activity.RESULT_CANCELED, null)

    // 2. Указываем Espresso: "когда будет запущен Intent с действием VIEW,
    // не открывай браузер, а просто верни результат 'CANCELED'".
    intending(hasAction("android.intent.action.VIEW")).respondWith(result)

    // 3. Кликаем на ссылку и проверяем, что появляется Toast с сообщением об ошибке.
    onView(withId(R.id.webTV)).perform(scrollTo(), click())
    onView(withText(R.string.no_application_can_handle_this_request))
        .inRoot(ToastMatcher()) // Специальный матчер для поиска Toast
        .check(matches(isDisplayed()))
}
----

Таким образом, `espresso-intents` позволяет надежно тестировать навигацию и взаимодействие с другими компонентами, не выходя за пределы вашего тестового окружения.
