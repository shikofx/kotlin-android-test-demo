`Intent` — это "клей", который связывает различные компоненты Android-приложения (Activity, Service) и даже разные приложения. Espresso предоставляет специальный артефакт `espresso-intents` для тестирования этих взаимодействий.

[[section-setup-intents]]
== Настройка `espresso-intents`

Добавьте зависимость в ваш файл `build.gradle`:

[source,groovy]
----
androidTestImplementation "androidx.test.espresso:espresso-intents:3.5.0"
----

[[section-verifying-intents]]
== API для тестирования Intent'ов

Для тестирования `Intent`'ов используется класс `androidx.test.espresso.intent.Intents`, который предоставляет два основных механизма:

*   **Верификация (Verification):** Проверка того, что исходящий `Intent` был отправлен и соответствует ожиданиям. Мы смотрим "назад" и проверяем: "А был ли отправлен вот такой Intent?".
*   **Стабинг (Stubbing):** Перехват исходящего `Intent`'а и возвращение "фейкового" результата, чтобы избежать запуска реальной `Activity`. Мы смотрим "вперед" и говорим: "Если будет отправлен вот такой Intent, не запускай его, а сразу верни вот этот результат".

Этот урок посвящен **верификации**.

=== Жизненный цикл тестирования

Чтобы Espresso мог "видеть" `Intent`'ы, отправляемые вашим приложением, необходимо явно инициализировать и освобождать перехватчик.

*   `Intents.init()`: Запускает запись всех `Intent`'ов, отправляемых приложением. Этот метод нужно вызывать *перед* выполнением действия, которое инициирует отправку `Intent`'а.
*   `Intents.release()`: Останавливает запись и очищает все записанные `Intent`'ы. Крайне важно вызывать этот метод, чтобы избежать утечек памяти и взаимовлияния тестов.

Идеальное место для этих вызовов — методы, помеченные аннотациями `@BeforeEach` и `@AfterEach` (для JUnit 5) или `@Before` и `@After` (для JUnit 4).

=== Проверка отправки Intent'а (`intended`)

Метод `intended()` — это основной инструмент для проверки. Он утверждает, что с момента вызова `init()` был отправлен `Intent`, соответствующий заданному матчеру.

`intended(Matcher<Intent> matcher, VerificationMode mode)`

*   `VerificationMode` позволяет указать, сколько раз мы ожидаем увидеть `Intent`:
**   `times(N)`: `Intent` был отправлен ровно `N` раз.
**   `never()`: `Intent` не был отправлен ни разу (аналогично `times(0)`).
**   Если режим не указан, по умолчанию используется `times(1)`.

=== Ключевые матчеры (`IntentMatchers`)

Для построения точных проверок `espresso-intents` предоставляет набор матчеров:

*   `hasAction(String)`: Проверяет действие `Intent`'а (например, `Intent.ACTION_VIEW`).
*   `hasData(Matcher<Uri>)`: Проверяет URI, переданный в `Intent`. Часто используется вместе с `UriMatchers` для проверки схемы, хоста или пути.
*   `hasComponent(String className)`: Проверяет, что `Intent` предназначен для запуска конкретного компонента (например, `MainActivity::class.java.name`). Очень полезен для проверки навигации внутри приложения.
*   `toPackage(String packageName)`: Проверяет, что `Intent` адресован определенному пакету (приложению).
*   `hasExtra(String key, T value)`: Проверяет наличие и значение "экстра"-данных, переданных вместе с `Intent`'ом.

=== Пример: Проверка открытия веб-ссылки из Activity

Возьмем реальный тест-кейс: пользователь запускает приложение, переходит на экран "О приложении" и кликает на ссылку. Мы должны проверить, что система пытается открыть браузер с правильным адресом.

Для этого тест должен запускать не отдельный фрагмент, а стартовую `Activity` (`SplashActivity`), чтобы приложение прошло полный и естественный цикл инициализации.

[source,kotlin]
----
import androidx.test.espresso.Espresso.onView
import androidx.test.espresso.action.ViewActions.* // click(), scrollTo()
import androidx.test.espresso.intent.Intents
import androidx.test.espresso.intent.Intents.*
import androidx.test.espresso.intent.matcher.IntentMatchers.*
import androidx.test.espresso.intent.matcher.UriMatchers
import by.pda.demoapp.android.view.activities.SplashActivity
import by.pda.demoapp.ui.common.test.ActivityTest
import org.hamcrest.Matchers.allOf
import org.junit.jupiter.api.AfterEach
import org.junit.jupiter.api.BeforeEach
import org.junit.jupiter.api.Test

class AboutFragmentLinkTest : ActivityTest<SplashActivity>(SplashActivity::class.java) {

    @BeforeEach
    fun setupIntents() {
        // 1. Инициализируем перехватчик Intent'ов
        Intents.init()
        // 2. Выполняем навигацию до нужного экрана
        openAboutFragment()
    }

    @AfterEach
    fun tearDownIntents() {
        // 4. Освобождаем ресурсы
        Intents.release()
    }

    @Test
    fun startWebBrowserIntentOnLinkClick() {
        // 1. Находим элемент и кликаем на него
        onView(withId(R.id.webTV)).perform(scrollTo(), click())

        // 2. Проверяем, что был отправлен Intent с нужными параметрами (один раз)
        intended(allOf(
            hasAction("android.intent.action.VIEW"), // Проверяем действие
            hasData(UriMatchers.hasHost("saucelabs.com")) // Проверяем хост в URI
        ))
    }
}
----

*   `Intents.intended()`: Проверяет, что был отправлен `Intent`, соответствующий указанному матчеру.
*   `hasAction()`: Матчер для проверки действия (`action`) в `Intent`.
*   `hasData(Matcher<Uri>)`: Матчер для проверки данных (`data`) в `Intent`. Он принимает вложенный матчер для `Uri`.
*   `UriMatchers.hasHost()`: Вложенный матчер, который проверяет только хост в `Uri`. Это более надежно, чем точное сравнение всей строки `hasData("https://saucelabs.com")`, так как игнорирует `www.` или слэш `/` в конце.
*   `allOf()`: Комбинирует несколько матчеров. Проверка будет успешной, только если `Intent` соответствует им всем.
