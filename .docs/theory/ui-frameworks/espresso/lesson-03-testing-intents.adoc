`Intent` — это "клей", который связывает различные компоненты Android-приложения (Activity, Service) и даже разные приложения. Espresso предоставляет специальный артефакт `espresso-intents` для тестирования этих взаимодействий.

[[section-setup-intents]]
== Настройка `espresso-intents`

Добавьте зависимость в ваш файл `build.gradle`:

[source,groovy]
----
androidTestImplementation "androidx.test.espresso:espresso-intents:3.5.0"
----

[[section-verifying-intents]]
== Проверка отправки Intent'а (`intended`)

Самый частый сценарий — проверить, что при нажатии на кнопку ваше приложение пытается запустить другую `Activity` с правильными параметрами.

Для этого в JUnit 5 необходимо вручную инициализировать и освобождать `Intents` в методах, помеченных аннотациями `@BeforeEach` и `@AfterEach`.

=== Пример: Проверка открытия веб-ссылки из Activity

Возьмем реальный тест-кейс: пользователь запускает приложение, переходит на экран "О приложении" и кликает на ссылку. Мы должны проверить, что система пытается открыть браузер с правильным адресом.

Для этого тест должен запускать не отдельный фрагмент, а стартовую `Activity` (`SplashActivity`), чтобы приложение прошло полный и естественный цикл инициализации.

[source,kotlin]
----
import androidx.test.espresso.Espresso.onView
import androidx.test.espresso.action.ViewActions.*
import androidx.test.espresso.intent.Intents
import androidx.test.espresso.intent.Intents.*
import androidx.test.espresso.intent.matcher.IntentMatchers.*
import androidx.test.espresso.intent.matcher.UriMatchers
import by.pda.demoapp.android.view.activities.SplashActivity
import by.pda.demoapp.ui.common.test.ActivityTest
import org.hamcrest.Matchers.allOf
import org.junit.jupiter.api.AfterEach
import org.junit.jupiter.api.BeforeEach
import org.junit.jupiter.api.Test

class AboutFragmentLinkTest : ActivityTest<SplashActivity>(SplashActivity::class.java) {

    @BeforeEach
    fun setupIntents() {
        // Инициализируем перехватчик Intent'ов перед каждым тестом
        Intents.init()
        // Выполняем навигацию до нужного экрана
        openAboutFragment()
    }

    @AfterEach
    fun tearDownIntents() {
        // Освобождаем ресурсы после каждого теста
        Intents.release()
    }

    @Test
    fun startWebBrowserIntentOnLinkClick() {
        // 1. Находим элемент и кликаем на него
        onView(withId(R.id.webTV)).perform(scrollTo(), click())

        // 2. Проверяем, что был отправлен Intent с нужными параметрами
        intended(allOf(
            hasAction("android.intent.action.VIEW"), // Проверяем действие
            hasData(UriMatchers.hasHost("saucelabs.com")) // Проверяем хост в URI
        ))
    }
}
----

*   `Intents.intended()`: Проверяет, что был отправлен `Intent`, соответствующий указанному матчеру.
*   `hasAction()`: Матчер для проверки действия (`action`) в `Intent`.
*   `hasData(Matcher<Uri>)`: Матчер для проверки данных (`data`) в `Intent`. Он принимает вложенный матчер для `Uri`.
*   `UriMatchers.hasHost()`: Вложенный матчер, который проверяет только хост в `Uri`. Это более надежно, чем точное сравнение всей строки `hasData("https://saucelabs.com")`, так как игнорирует `www.` или слэш `/` в конце.
*   `allOf()`: Комбинирует несколько матчеров. Проверка будет успешной, только если `Intent` соответствует им всем.

== Стабинг (Stubbing) Intent'ов (`intending`)

Иногда ваше приложение запускает внешние `Activity`, например, камеру или галерею. В тестах мы не хотим открывать реальную камеру. Вместо этого мы можем "застабать" (от англ. stub) этот `Intent` — перехватить его и вернуть заранее подготовленный результат, как если бы пользователь сделал фото.

Для этого используется `Intents.intending()`.

=== Пример: Стабинг выбора изображения из галереи

[source,kotlin]
----
@Test
fun pickingImage_displaysItInImageView() {
    // 1. Создаем "фейковый" результат, как будто мы выбрали картинку
    val resultData = Intent()
    val imageUri = Uri.parse("content://fake/image.jpg")
    resultData.data = imageUri
    val result = Instrumentation.ActivityResult(Activity.RESULT_OK, resultData)

    // 2. Указываем Espresso: "когда будет запущен Intent на выбор контента,
    // не открывай галерею, а верни наш фейковый результат"
    intending(hasAction(Intent.ACTION_PICK)).respondWith(result)

    // 3. Кликаем на кнопку, которая запускает выбор изображения
    onView(withId(R.id.pick_image_button)).perform(click())

    // 4. Проверяем, что в нашем ImageView появилась "выбранная" картинка
    onView(withId(R.id.image_view)).check(matches(withImageUri(imageUri))) // withImageUri - кастомный матчер
}
----

*   `intending()`: Устанавливает правило перехвата.
*   `respondWith()`: Указывает, какой результат нужно вернуть при перехвате.

Таким образом, `espresso-intents` позволяет надежно тестировать навигацию и взаимодействие с другими компонентами, не выходя за пределы вашего тестового окружения.
