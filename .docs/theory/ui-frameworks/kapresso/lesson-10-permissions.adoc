== Permissions: Проблема в UI-тестах

Современные Android-приложения активно используют систему разрешений (Permissions) для доступа к конфиденциальным данным или функциям устройства (камера, геолокация, контакты, хранилище). В UI-тестах это создает проблему:

*   **Системные диалоги:** При первом запросе разрешения появляется системный диалог, который не контролируется Espresso.
*   **Нестабильность:** Ручное взаимодействие с диалогом или его игнорирование приводит к нестабильным тестам.
*   **Изоляция:** Для каждого теста может потребоваться разное состояние разрешений.

Kaspresso предоставляет удобный API для программного управления разрешениями, обходя системные диалоги и обеспечивая стабильность тестов.

[[section-kaspresso-permissions-api]]
== Управление разрешениями с Kaspresso

Kaspresso позволяет легко предоставлять (`grant`) и отзывать (`revoke`) разрешения Android прямо из теста, используя объект `device.permissions`.

=== Пример: Тестирование функции, требующей разрешения на камеру

Предположим, у нас есть экран, который использует камеру. Мы хотим протестировать два сценария: когда разрешение предоставлено и когда оно отозвано.

```kotlin
import com.kaspersky.kaspresso.testcases.api.testcase.TestCase
import com.example.app.ui.main.MainActivity // Ваша Activity, которая использует камеру
import org.junit.Rule
import org.junit.Test
import android.Manifest
import androidx.test.ext.junit.rules.ActivityScenarioRule
import com.kaspersky.kaspresso.screens.KScreen
import com.agoda.kakao.text.KButton
import com.agoda.kakao.image.KImageView
import com.example.app.R

object CameraScreen : KScreen<CameraScreen>() {
    override val layoutId: Int? = R.layout.activity_camera
    val openCameraButton = KButton { withId(R.id.open_camera_button) }
    val cameraPreview = KImageView { withId(R.id.camera_preview) }
    val permissionDeniedMessage = KTextView { withId(R.id.permission_denied_message) }
}

class CameraPermissionTest : TestCase() {

    @get:Rule
    val activityRule = ActivityScenarioRule(MainActivity::class.java)

    @Test
    fun cameraFeature_worksWhenPermissionGranted() = run {
        step("Предоставить разрешение на камеру") {
            device.permissions.grant(Manifest.permission.CAMERA)
        }
        step("Проверить, что камера открывается") {
            CameraScreen {
                openCameraButton.click()
                cameraPreview.isDisplayed()
            }
        }
    }

    @Test
    fun cameraFeature_showsErrorWhenPermissionDenied() = run {
        step("Отозвать разрешение на камеру") {
            device.permissions.revoke(Manifest.permission.CAMERA)
        }
        step("Проверить, что отображается сообщение об ошибке") {
            CameraScreen {
                openCameraButton.click()
                permissionDeniedMessage.isDisplayed()
                permissionDeniedMessage.hasText(R.string.camera_permission_denied)
            }
        }
    }
}
```

=== Важные моменты:

*   **`device.permissions.grant(Manifest.permission.CAMERA)`**: Программно предоставляет указанное разрешение. Kaspresso использует `adb shell pm grant` под капотом.
*   **`device.permissions.revoke(Manifest.permission.CAMERA)`**: Программно отзывает указанное разрешение. Kaspresso использует `adb shell pm revoke`.
*   **Изоляция:** Важно, чтобы каждый тест начинался с известного состояния разрешений. Используйте `before()` или `after()` в `KTestCase` для сброса разрешений, если это необходимо.

Управление разрешениями с Kaspresso значительно упрощает тестирование сценариев, которые зависят от них, делая тесты более надежными и предсказуемыми.
