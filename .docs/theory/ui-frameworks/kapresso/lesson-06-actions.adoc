== Actions: Взаимодействие с элементами

После того как Kaspresso нашел элемент с помощью `ViewMatcher`, следующим шагом является выполнение над ним какого-либо действия (`ViewAction`). Kaspresso предоставляет удобный и читаемый DSL для выполнения этих действий, скрывая под капотом сложную логику обеспечения стабильности.

```kotlin
import com.kaspersky.kaspresso.testcases.api.testcase.TestCase
import com.example.app.ui.login.LoginActivity
import org.junit.Rule
import org.junit.Test
import androidx.test.ext.junit.rules.ActivityScenarioRule

class LoginTest : TestCase() {

    @get:Rule
    val activityRule = ActivityScenarioRule(LoginActivity::class.java)

    @Test
    fun loginWithValidCredentials_shouldOpenProductCatalog() = run {
        LoginScreen {
            // Действие: ввод текста
            usernameField.typeText("standard_user")

            // Действие: ввод текста и закрытие клавиатуры
            passwordField.replaceText("secret_sauce")

            // Действие: клик
            loginButton.click()
        }
        // ...
    }
}
```

[[section-kaspresso-action-stability]]
== Механизмы стабильности для Actions

Когда вы вызываете `loginButton.click()`, Kaspresso не просто выполняет `Espresso.onView(...).perform(click())`. Он запускает целый "конвейер стабильности", который гарантирует, что действие будет выполнено надежно:

1.  **Ожидание `IdlingResource`:** Kaspresso ждет, пока все зарегистрированные `IdlingResource` не станут свободными.
2.  **Поиск элемента (с повторами):** Как мы обсуждали в предыдущем уроке, Kaspresso ищет элемент, повторяя попытки до истечения таймаута.
3.  **Проверка доступности (с повторами):** Перед выполнением действия Kaspresso убеждается, что элемент находится в подходящем состоянии (например, он видим, активен, не перекрыт другими `View`). Если проверка не проходит, Kaspresso также будет повторять ее до истечения таймаута.
4.  **Выполнение действия:** Только после всех успешных проверок Kaspresso выполняет сам `ViewAction` (например, `click()`).
5.  **Обработка ошибок и логирование:** Если на любом из этапов происходит сбой (даже после всех повторов), Kaspresso генерирует подробный отчет об ошибке, включая скриншот, и детально логирует все шаги.

Этот многоступенчатый подход решает подавляющее большинство проблем, связанных с нестабильностью UI-тестов.

=== Основные Actions в Kaspresso

*   `click()`: Обычный клик.
*   `doubleClick()`: Двойной клик.
*   `longClick()`: Долгий клик.
*   `typeText("some text")`: Ввод текста (добавляет к существующему).
*   `replaceText("new text")` / `clearText()`: Замена или очистка текста.
*   `scrollTo()`: Прокрутка до элемента.
*   `swipeUp()`, `swipeDown()`, `swipeLeft()`, `swipeRight()`: Свайпы по элементу.
