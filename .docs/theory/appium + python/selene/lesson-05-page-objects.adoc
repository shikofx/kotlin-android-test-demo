`selene` делает реализацию паттерна Page Object еще более элегантной и лаконичной, так как нам больше не нужно передавать `driver` в каждый объект страницы.

[[section-selene-po]]
== Page Object с `selene`

Мы можем описать элементы как свойства класса, а методы будут инкапсулировать логику взаимодействия.

=== Пример: `LoginScreen` на `selene`

```python
# pages/login_screen.py

from selene import s, have
from appium.webdriver.common.appiumby import AppiumBy

class LoginScreen:
    def __init__(self):
        # Описываем элементы как Element
        self.username_input = s((AppiumBy.ID, "com.example.app:id/username_input"))
        self.password_input = s((AppiumBy.ID, "com.example.app:id/password_input"))
        self.login_button = s((AppiumBy.ID, "com.example.app:id/login_button"))

    # Описываем высокоуровневые действия
    def login(self, username, password):
        self.username_input.type(username)
        self.password_input.type(password)
        self.login_button.click()
        return ProductsScreen()

class ProductsScreen:
    def __init__(self):
        self.title = s((AppiumBy.XPATH, "//*[@text='Products']"))

    def should_have_title(self, text):
        self.title.should(have.text(text))
```

=== Использование в тесте

```python
# tests/test_login.py

from pages.login_screen import LoginScreen

def test_successful_login(mobile_management):
    login_screen = LoginScreen()
    products_screen = login_screen.login("standard_user", "secret_sauce")
    products_screen.should_have_title("Products")
```

Тест становится цепочкой вызовов (fluent interface), что делает его максимально читаемым и выразительным. `selene` берет на себя всю сложность ожидания элементов и проверок, оставляя в тесте только чистую бизнес-логику.
