Вместо стандартных `assert` `selene` предлагает использовать **условия (Conditions)**. Это набор готовых проверок, которые можно применять к элементам с помощью метода `.should()`.

[[section-should-methods]]
== Метод `should()`

*   `element.should(condition)`: Проверяет, что элемент соответствует условию (например, `be.visible`).
*   `element.should(have.text("..."))`: Проверяет, что элемент имеет какое-то свойство.

Как и действия, проверки тоже имеют **встроенные ожидания**. `element.should(be.visible)` будет ждать, пока элемент не станет видимым, и только потом проверит это.

[[section-common-conditions]]
== Основные условия (`be` и `have`)

Условия импортируются из `selene.support.conditions`.

*   **`be.visible`**: Элемент видим.
*   **`be.hidden`**: Элемент скрыт.
*   **`be.present`**: Элемент существует в DOM (аналог `exist` в Selenide).
*   **`be.enabled`**: Элемент активен.
*   **`be.selected`**: Элемент выбран.

*   **`have.text("expected text")`**: Элемент имеет точный текст.
*   **`have.exact_text("...")`**: Синоним `have.text`.
*   **`have.text_containing("...")`**: Текст элемента содержит подстроку.
*   **`have.attribute("name").value("value")`**: Элемент имеет атрибут с нужным значением.

[[section-example]]
== Пример теста с проверками

```python
from selene import s, be, have
from appium.webdriver.common.appiumby import AppiumBy

def test_successful_login(mobile_management):
    s((AppiumBy.ID, "com.example.app:id/username_input")).type("standard_user")
    s((AppiumBy.ID, "com.example.app:id/password_input")).type("secret_sauce")
    s((AppiumBy.ID, "com.example.app:id/login_button")).click()

    # Проверяем, что заголовок на следующем экране видим и имеет правильный текст
    s((AppiumBy.XPATH, "//*[@text='Products']")) \
        .should(be.visible) \
        .should(have.text("Products"))
```

Код становится декларативным и очень легко читается. Если проверка не пройдет, `selene` выдаст подробное сообщение об ошибке.
