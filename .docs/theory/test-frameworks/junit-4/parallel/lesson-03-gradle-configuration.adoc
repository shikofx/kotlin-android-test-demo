Самый распространенный и мощный способ запускать JUnit 4 тесты параллельно в Android-проекте — это настройка Gradle. Gradle может запускать тесты в нескольких параллельных процессах-воркерах.

[[section-gradle-config]]
== Конфигурация в `build.gradle.kts`

Настройка производится в блоке `testOptions` для `unitTests` или `androidTests`.

```kotlin
// build.gradle.kts (app)

android {
    // ...

    testOptions {
        unitTests.all { test ->
            test.useJUnitPlatform() // Если используете JUnit 5
            // Для JUnit 4 эта строка не нужна, но вот как настраивается параллелизм:

            test.maxParallelForks = (Runtime.getRuntime().availableProcessors() / 2).takeIf { it > 0 } ?: 1
        }
    }
}
```

=== `maxParallelForks`

*   **`maxParallelForks`**: Это ключевое свойство. Оно указывает Gradle, сколько независимых JVM-процессов (воркеров) можно запустить для выполнения тестов. Каждый воркер будет последовательно выполнять свою порцию тестов.

*   **Как это работает?** Gradle распределяет все тестовые классы между доступными воркерами. Например, если у вас 100 тестовых классов и `maxParallelForks = 4`, Gradle запустит 4 процесса. Каждый процесс получит примерно по 25 классов и будет выполнять их один за другим. Общее время выполнения сократится почти в 4 раза.

*   **Пример значения:** `(Runtime.getRuntime().availableProcessors() / 2)` — это распространенная практика, чтобы не перегружать машину, на которой выполняются тесты, оставляя ресурсы для других задач.

[IMPORTANT]
====
Этот механизм обеспечивает параллелизм на уровне **процессов**, а не потоков внутри одного процесса. Это более надежный, но и более ресурсоемкий способ изоляции тестов друг от друга.
====
