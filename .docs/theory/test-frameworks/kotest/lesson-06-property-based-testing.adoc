**Property-Based Testing (PBT)** — это продвинутая техника тестирования, где вы не придумываете конкретные входные данные, а описываете **свойства (properties)**, которым ваша функция должна удовлетворять для *любых* валидных данных. Фреймворк затем сам генерирует сотни или тысячи случайных входных данных и пытается найти контрпример, который нарушает это свойство.

Это невероятно мощный способ для поиска неожиданных граничных случаев.

[[section-pbt-example]]
== Пример: Свойства сложения

Давайте проверим простое свойство: `a + b == b + a` (коммутативность).

```kotlin
import io.kotest.core.spec.style.StringSpec
import io.kotest.property.forAll

class AdditionPropertiesTest : StringSpec({
    "addition should be commutative" {
        forAll<Int, Int> { a, b ->
            a + b == b + a
        }
    }
})
```

=== Что здесь происходит?

*   `forAll<Int, Int> { a, b -> ... }`: Мы говорим Kotest: "Для всех возможных целых чисел `a` и `b`...".
*   `a + b == b + a`: Лямбда должна вернуть `true`, если свойство выполняется для данной пары `a` и `b`.
*   Kotest автоматически сгенерирует множество пар `(a, b)`, включая положительные, отрицательные числа, ноль, `Int.MAX_VALUE`, `Int.MIN_VALUE`, и проверит, выполняется ли свойство.
*   Если Kotest найдет контрпример (пару, для которой `a + b != b + a`), он не просто сообщит об ошибке, но и попытается "упростить" (shrink) этот контрпример до минимально возможного, чтобы его было легче отладить.

[[section-pbt-android]]
== Применение в реальных задачах

PBT отлично подходит для тестирования:
*   **Парсеров:** "Любой объект, который я сериализую, а затем десериализую, должен быть равен исходному".
*   **Функций-валидаторов:** "Любая строка, сгенерированная по определенным правилам, должна проходить валидацию".
*   **Математических вычислений:** Проверка свойств, таких как ассоциативность, дистрибутивность и т.д.

Property-Based Testing — это следующий шаг после Data-Driven Testing, который позволяет достичь еще более высокого уровня уверенности в корректности вашего кода.
