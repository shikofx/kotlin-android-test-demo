== `AndroidJUnitRunner`

`AndroidJUnitRunner` — это класс из библиотеки `androidx.test:runner`, который отвечает за запуск JUnit-тестов на Android-устройстве. Он управляет жизненным циклом приложения, загружает тестовые классы и выполняет их.

Вы настраиваете его в файле `build.gradle.kts` вашего модуля:

```kotlin
// build.gradle.kts (app)

android {
    defaultConfig {
        testInstrumentationRunner = "androidx.test.runner.AndroidJUnitRunner"
    }
}
```

Когда вы запускаете инструментальные тесты (например, командой `./gradlew connectedCheck`), именно `AndroidJUnitRunner` берет на себя всю работу по их выполнению на эмуляторе или устройстве.

[[section-rules]]
== `TestRule`

`TestRule` — это механизм из JUnit 4, который позволяет выполнять определенный код до и после выполнения каждого тестового метода. Это очень удобно для подготовки и очистки тестового окружения.

AndroidX Test предоставляет несколько полезных правил, например:

*   `ActivityScenarioRule`: Запускает указанную `Activity` перед каждым тестом и закрывает ее после.
*   `ServiceTestRule`: Позволяет тестировать `Service` компоненты.
*   `GrantPermissionRule`: Предоставляет приложению необходимые разрешения во время теста.

Хотя `TestRule` — это концепция JUnit 4, она широко используется в Android-тестировании. В JUnit 5 похожая функциональность достигается с помощью механизма расширений (`Extensions`), как мы видели на примере `InstantExecutorExtension`.

В следующем уроке мы подробно рассмотрим `ActivityScenarioRule` — одно из самых важных правил для UI-тестирования.
