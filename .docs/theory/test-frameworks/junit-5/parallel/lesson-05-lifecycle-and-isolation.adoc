Режим жизненного цикла экземпляра тестового класса, управляемый аннотацией `@TestInstance`, напрямую влияет на то, насколько легко или сложно обеспечить безопасность при параллельном выполнении.

[[section-per-method]]
== `@TestInstance(Lifecycle.PER_METHOD)` (по умолчанию)

*   **Как работает:** Перед каждым тестовым методом (`@Test`) создается **новый экземпляр** тестового класса.
*   **Влияние на параллелизм:** Это **самый безопасный режим** для параллельного выполнения. Поскольку каждый тест работает со своим собственным экземпляром класса, они не могут конфликтовать из-за общих полей этого класса. Каждый тест полностью изолирован.

```kotlin
@TestInstance(TestInstance.Lifecycle.PER_METHOD) // Это поведение по умолчанию
class SafeParallelTest {
    var counter = 0 // Это поле безопасно

    @Test fun testA() { counter++; /* ... */ } // counter будет 0 в начале
    @Test fun testB() { counter++; /* ... */ } // counter тоже будет 0 в начале
    // testA и testB могут безопасно выполняться параллельно
}
```

[[section-per-class]]
== `@TestInstance(Lifecycle.PER_CLASS)`

*   **Как работает:** Для всех тестовых методов в классе создается **один-единственный экземпляр** тестового класса.
*   **Влияние на параллелизм:** Этот режим **опасен** при параллельном выполнении. Если тесты изменяют общие поля класса, это немедленно приведет к состоянию гонки.

```kotlin
@TestInstance(TestInstance.Lifecycle.PER_CLASS)
@Execution(ExecutionMode.CONCURRENT) // Включаем параллельное выполнение методов
class UnsafeParallelTest {
    var counter = 0 // ОПАСНО: это общее изменяемое состояние

    @Test fun testA() { counter++ } // Может выполниться одновременно с testB
    @Test fun testB() { counter++ } // Результат `counter` будет непредсказуем
}
```

**Вывод:** При использовании параллельного выполнения настоятельно рекомендуется придерживаться режима `@TestInstance(Lifecycle.PER_METHOD)`, чтобы обеспечить максимальную изоляцию тестов и избежать проблем с общими полями класса.
