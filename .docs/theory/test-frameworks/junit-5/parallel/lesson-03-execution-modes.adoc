JUnit 5 предоставляет два режима выполнения, которые можно настраивать как глобально, так и для отдельных тестовых классов.

[[section-modes]]
== Режимы выполнения

*   **`SAME_THREAD`**:
    *   Тестовые классы могут выполняться параллельно друг с другом.
    *   Но все методы *внутри одного класса* (`@Test`, `@BeforeEach`, `@AfterEach`) выполняются **последовательно**, в одном потоке.
    *   Это безопасный режим по умолчанию, если вы не уверены в потокобезопасности ваших тестов.

*   **`CONCURRENT`**:
    *   Тестовые классы могут выполняться параллельно друг с другом.
    *   И тестовые методы *внутри одного класса* также могут выполняться **параллельно** друг с другом.
    *   Этот режим обеспечивает максимальную параллелизацию, но требует, чтобы тесты внутри класса были полностью независимы и не использовали общие изменяемые ресурсы.

[[section-execution-annotation]]
== Аннотация `@Execution`

Хотя режимы можно задать глобально в `junit-platform.properties`, часто бывает необходимо переопределить их для конкретного тестового класса. Для этого используется аннотация `@Execution`.

=== Пример

Предположим, глобально у нас включен режим `CONCURRENT`, но есть один старый тестовый класс, который не является потокобезопасным. Мы можем принудительно заставить его выполняться последовательно.

```kotlin
import org.junit.jupiter.api.parallel.Execution
import org.junit.jupiter.api.parallel.ExecutionMode

@Execution(ExecutionMode.SAME_THREAD)
class LegacyUnsafeTest {

    private var sharedState = 0

    @Test fun testA() { sharedState++ }
    @Test fun testB() { sharedState++ }
    // Эти тесты будут выполняться последовательно, избегая гонки за `sharedState`
}
```

И наоборот, если по умолчанию стоит `SAME_THREAD`, вы можете пометить полностью независимый класс аннотацией `@Execution(ExecutionMode.CONCURRENT)`, чтобы ускорить его выполнение.
