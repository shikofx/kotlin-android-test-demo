[[section-why-parallel]]
== Зачем нужна параллелизация?

По мере роста проекта количество тестов (особенно интеграционных и UI) увеличивается. Время, необходимое для полного прогона всех тестов, может стать значительным (десятки минут или даже часы), замедляя CI/CD пайплайн и снижая продуктивность разработчиков.

**Параллельное выполнение тестов** — это возможность JUnit 5 запускать несколько тестов одновременно в разных потоках. Это позволяет значительно сократить общее время выполнения тестового набора за счет утилизации многоядерных процессоров.

Например, если у вас есть 100 тестов, каждый из которых выполняется 1 секунду, последовательное выполнение займет 100 секунд. При запуске в 4 параллельных потока общее время может сократиться до ~25 секунд.

[[section-challenges]]
== Проблемы параллелизации: Состояние Гонки

Параллельное выполнение несет с собой и проблемы. Главная из них — **конфликты за общие изменяемые ресурсы (shared mutable state)**. Если несколько тестов одновременно пытаются прочитать и записать один и тот же ресурс, это приводит к **состоянию гонки (race condition)** и, как следствие, к непредсказуемым результатам и нестабильным ("flaky") тестам.

Примеры общих ресурсов:
*   Статические поля в классах.
*   Системные свойства (`System.properties`).
*   Общие файлы, базы данных, сетевые порты.

JUnit 5 предоставляет мощные механизмы для безопасного управления этими ресурсами, которые мы рассмотрим в следующих уроках.
