[[section-what-is-bdd]]
== Что такое Behavior-Driven Development (BDD)?

**BDD (Разработка через поведение)** — это методология разработки, которая является развитием TDD (Test-Driven Development). Основная идея BDD — описывать поведение системы на естественном, понятном для всех языке, а затем использовать эти описания как основу для автоматизированных тестов.

BDD помогает наладить коммуникацию между разработчиками, тестировщиками и бизнес-аналитиками.

[[section-gherkin]]
== Синтаксис Gherkin: Given-When-Then

Для описания сценариев в BDD используется специальный язык Gherkin. Сценарий строится по шаблону **Given-When-Then**:

*   **Given (Дано):** Описывает начальное состояние системы или контекст. (Предусловия)
*   **When (Когда):** Описывает ключевое действие, которое выполняет пользователь.
*   **Then (Тогда):** Описывает ожидаемый результат или изменение состояния системы.

**Пример сценария:**
```gherkin
Feature: Авторизация пользователя

  Scenario: Успешный вход с валидными данными
    Given Пользователь находится на экране входа
    When  Он вводит валидный логин и пароль
    And   Нажимает кнопку "Войти"
    Then  Он должен увидеть экран каталога продуктов
```

[[section-bdd-with-kaspresso]]
== Реализация BDD-стиля в Kaspresso

Kaspresso идеально подходит для написания тестов в BDD-стиле благодаря своей функции `step()`. Мы можем использовать `step()` для каждого блока Given-When-Then, что делает код теста точным отражением Gherkin-сценария.

```kotlin
import com.kaspersky.kaspresso.testcases.api.testcase.TestCase

class LoginBddTest : TestCase() {
    @Test
    fun successfulLoginWithValidCredentials() = run {
        step("Given: Пользователь находится на экране входа") {
            // Этот шаг выполняется неявно, так как мы запускаем LoginActivity
        }
        step("When: Он вводит валидный логин и пароль и нажимает кнопку 'Войти'") {
            LoginScreen {
                usernameField.typeText("standard_user")
                passwordField.typeText("secret_sauce")
                loginButton.click()
            }
        }
        step("Then: Он должен увидеть экран каталога продуктов") {
            ProductCatalogScreen {
                title.isDisplayed()
            }
        }
    }
}
```

**Преимущества такого подхода:**
*   **Живая документация:** Тесты становятся "живой" документацией, которая всегда актуальна.
*   **Понятно для всех:** Любой член команды, даже не-технический специалист, может прочитать тест и понять, что он проверяет.
*   **Структура:** Тесты имеют четкую и логичную структуру.
