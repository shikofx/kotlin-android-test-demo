= Тест-кейсы для интеграции `AppDao`

Этот документ описывает интеграционные тест-кейсы для интерфейса `AppDao.java`, фокусируясь на его взаимодействии с базой данных Room.

'''

== Цель
Проверить корректность CRUD-операций (создание, чтение, обновление, удаление) и логики сортировки данных на уровне базы данных.

== Тестовое окружение
*   **Фреймворк:** JUnit 5
*   **База данных:** In-memory база данных Room (`inMemoryDatabaseBuilder`) для обеспечения изоляции и скорости тестов.
*   **Runner:** `AndroidJUnit4`

'''

== Тест-кейсы

[cols="2,3,4a,4a,2"]
|===
| ID | Сценарий | Шаги | Ожидаемый результат | Тип теста

| *DAO-1* | **Happy Path: Вставка и чтение** | 1. Создать объект `ProductModel`.
2. Вызвать `insertProduct()` для сохранения в БД.
3. Вызвать `getAllProducts()` для получения всех продуктов. | 1. Возвращенный список не пуст и имеет размер 1.
2. Продукт в списке идентичен тому, который был вставлен. | Позитивный

| *DAO-2* | **Happy Path: Удаление** | 1. Вставить продукт (как в DAO-1).
2. Вызвать `delete()` с вставленным продуктом.
3. Снова вызвать `getAllProducts()`. | Возвращенный список пуст. | Позитивный

| *DAO-3* | **Сортировка: По имени (по возрастанию)** | 1. Вставить три продукта с именами "C", "A", "B".
2. Вызвать `getPersonsSortByAscName()`. | Возвращенный список содержит продукты в порядке "A", "B", "C". | Позитивный

| *DAO-4* | **Сортировка: По имени (по убыванию)** | 1. Вставить три продукта с именами "C", "A", "B".
2. Вызвать `getPersonsSortByDescName()`. | Возвращенный список содержит продукты в порядке "C", "B", "A". | Позитивный

| *DAO-5* | **Чтение из пустой БД** | 1. Не вставлять никаких продуктов.
2. Вызвать `getAllProducts()`. | Возвращенный список не является null, но пуст. | Негативный

| *DAO-6* | **Чтение конкретного продукта** | 1. Вставить продукт с известным ID (например, 1).
2. Вызвать `getProduct(1)`. | Возвращенный объект `ProductModel` не является null и соответствует вставленному продукту. | Позитивный
|===
